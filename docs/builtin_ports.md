# Yajir 組み込みポート リファレンス（スクリプト作成者向け）

最初から使えるポートの一覧です。スクリプトを書くときの早見表として使ってください。
言語そのものの文法（`ON … END`／スロット／`->` の意味など）は言語仕様書を参照してください。
ここでは「どんなポートがあって、何を入れると何が出るか」だけを説明します。

> ノート: `STDOUT` / `LED1` / `DELAY` などはホスト（C側）が用意するポートで、機器ごとに異なります。
> 本書のサンプルで使う `STDOUT` は「ホストが用意した出力ポートの一例」として読んでください。

> **大文字・小文字は区別します（ケースセンシティブ）。** ポート名・キーワードは大文字で正確に書いてください（`STRTOL` は有効、`strtol` は未知のポート扱い）。

---

## 結果の受け取り方（まず最初に）

ポートに値を流す（`値 -> ポート`）と、計算結果は次の2か所のどちらかに入ります。

|産出するもの|結果の置き場所|受け取り方|
|-|-|-|
|整数（int）|`RESULT`|`RESULT -> GVAR[0]`|
|文字列（str）|`SRESULT`|`SRESULT -> SGVAR[0]`|

各ポートが「int産出」か「str産出」かは、以下の表の **産出** 列を見てください。

```
"hello" -> COUNTER      # COUNTER は int産出
RESULT  -> GVAR[0]      # → 5

"abc" -> UPPER          # UPPER は str産出
SRESULT -> SGVAR[0]     # → "ABC"
```

複数のポートを `->` で数珠つなぎ（チェイン）にすると、途中の `RESULT`/`SRESULT` は
自動で次の段へ渡るので、自分で書かなくても繋がります（末尾の例を参照）。

## システム情報ポート

読み出すと現在の状態を返す入力ポートです。

|ポート|産出|説明|例|
|-|-|-|-|
|`STATUS`|int|直近のエラー状態ビット（`ERR_*` の OR）|`STATUS -> GVAR[0]`|
|`CODE_USED`|int|ロード中スクリプトのバイトコード使用量（バイト）|`CODE_USED -> GVAR[0]`|
|`STR_USED`|int|文字列定数プールの使用量（バイト）|`STR_USED -> GVAR[0]`|
|`VERSION`|str|言語バージョン文字列|`VERSION -> SGVAR[0]`|

```
# 起動時に環境を表示する例
"Yajir v"  -> STDOUT
VERSION    -> STDOUT          # → 0.4.2
"code: ", CODE_USED -> STDOUT
"str:  ", STR_USED  -> STDOUT
```

### エラー定数

`STATUS` と AND して、どのエラーが立っているか調べるための定数です（読み取り専用）。

|定数|意味|
|-|-|
|`ERR_QUEUE_OVF`|イベントキュー溢れ|
|`ERR_TIMER_FULL`|タイマ枠が一杯|
|`ERR_DIVZERO`|ゼロ除算が起きた|
|`ERR_STR_TRUNC`|文字列が切り詰められた|
|`ERR_BUDGET`|`REPEAT` が命令数上限で打ち切られた（v0.4.4）|

```
STATUS -> GVAR[0]
# 「ゼロ除算が起きていたら…」のような判定に使う（演算は言語仕様を参照）
```

## 文字列ユーティリティ

文字列処理ポートです。**入力は数も型も緩め** ＝ 引数が足りない/型が違うときは
プログラムを止めず、無難な既定値や空文字に縮退します（例: 範囲外は `""`、解析不能は `0`）。

### 一覧

|ポート|産出|入力|説明|
|-|-|-|-|
|`COUNTER`|int|`str`|文字列のバイト長|
|`EQUALS`|int|`strA, strB`|一致なら `1`、不一致なら `0`|
|`FINDER`|int|`hay, needle`|`needle` の最初の出現位置（**1始まり**）。無ければ `0`|
|`STRTOL`|int|`str [, base]`|文字列を整数へ。**既定は16進**。第2引数で基数指定（2〜36, 0=自動）|
|`CHR`|str|`int`|整数を1文字の文字列へ（グリフ化）。`STRTOL`（str→int）の対。受信バイトのエコー等に|
|`SLICER`|str|`str, start, len`|部分文字列（`start` は**1始まり**）|
|`MERGER`|str|`strA, strB`|連結|
|`FORMATTER`|str|`fmt, args…`|`printf` 風の整形（後述）|
|`FIELD`|str|`str [, delim], N`|区切りで **N番目（1始まり）** のトークン|
|`UPPER`|str|`str`|大文字化（ASCII）|
|`LOWER`|str|`str`|小文字化（ASCII）|
|`TRIMMER`|str|`str`|前後の空白・タブ・CR/LF を除去（中間は保持）|

### 例

```
# 長さ・一致・検索
"hello"          -> COUNTER   # RESULT = 5
"abc", "abc"     -> EQUALS    # RESULT = 1
"this is a pen", "is" -> FINDER   # RESULT = 3（"th[is]…"）

# 文字列→整数（既定16進）
"00FF"     -> STRTOL          # RESULT = 255
"100", 10  -> STRTOL          # RESULT = 100（10進指定）

# 整数→1文字（グリフ化）。文字リテラル 'A' は int 65 の別表記
65   -> CHR                   # SRESULT = "A"
'A'  -> CHR                   # SRESULT = "A"（'A' == 65）
ARG[0] -> CHR -> STDOUT       # 受信バイト(int)を文字でエコー

# 切り出し・連結（1始まり）
"HELLO WORLD", 1, 5 -> SLICER # SRESULT = "HELLO"
"NO ", "MUSIC"      -> MERGER # SRESULT = "NO MUSIC"

# 大小・トリム
"Send_Ok"      -> UPPER       # SRESULT = "SEND_OK"
"  hi there  " -> TRIMMER     # SRESULT = "hi there"
```

### FORMATTER（printf 風整形）

`fmt` の `%…` 変換指定をそのまま標準の整形に渡します。フラグ・幅・精度
（`%4d` `%-10s` `%08x` `%+d` `%%`）がそのまま使えます。

```
"id=%04d name=%s", 7, "jiro" -> FORMATTER
SRESULT -> SGVAR[0]          # "id=0007 name=jiro"
```

* 整数を取る変換: `d i u o x X c`
* 文字列を取る変換: `s`
* `%%` はそのまま `%`
* 危険・非対応の変換（`%n` `%f` など）は**整形を実行せず、そのまま文字として出力**します（安全側）。

### FIELD（区切りでトークン抽出）

UART 応答などを分解するのに便利です。

```
"SEND 0001 0002 OK", " ", 3 -> FIELD   # SRESULT = "0002"（3番目）
"a,,b,c", ",", 2            -> FIELD   # SRESULT = "b"（連続区切りは詰める）
"  hello   world  ", 2     -> FIELD   # SRESULT = "world"（2引数＝空白区切りの略記）
```

* 区切り（`delim`）は **「区切り文字の集合」**。`" ,"` なら空白とカンマのどちらでも区切ります。
* 連続した区切りはまとめて1つ扱い、前後の区切りは無視します（＝「N番目の単語」を取る挙動）。
* `N` が範囲外、または空文字列のときは `""`。

## 数値ユーティリティ

数値の変換・加工ポートです（v0.4.3）。すべて **int産出**（結果は `RESULT`）。
文字列ユーティリティと同じく、引数が足りないときは 0 埋めで縮退します（止まりません）。

|ポート|入力|説明|
|-|-|-|
|`RAND`|（なし・値源）|非負の擬似乱数 `0 .. 2147483647` を返す。範囲は `RAND % N` で作る|
|`SEED`|`seed`|乱数を再シードする（`値 -> SEED`）。同じ種なら同じ列（再現的）|
|`CLAMP`|`x, lo, hi`|`x` を `lo`〜`hi` に収める（範囲外は端に張り付く）|
|`MAP`|`x, inLo, inHi, outLo, outHi`|`x` を入力レンジから出力レンジへ線形変換|
|`MIN`|`a, b, …`|最小値（可変個）|
|`MAX`|`a, b, …`|最大値（可変個）|
|`ABS`|`x`|絶対値|

```
# 乱数（0..2^31-1）。範囲は % で作る
RAND % 6 + 1 -> GVAR[0]        # 1..6 のサイコロ
NOW -> SEED                    # 起動ごとに種を変える（実機は SEED に雑音源などでも可）

# 線形変換と飽和（ADC実務の定番）。※ ADC / PWM はホスト提供ポートの一例
ADC, 0, 4095, 0, 100 -> MAP    # 12bit ADC を 0..100% へ
RESULT -> VAR[0]
VAR[0], 0, 100 -> CLAMP -> PWM # 念のため 0..100 に収めて出力

# 最小・最大・絶対値
3, 9, 1, 5 -> MIN              # RESULT = 1
GVAR[1], GVAR[2] -> MAX        # 大きい方
GVAR[1] - GVAR[2] -> ABS       # 差の大きさ（絶対値）
```

* `RAND` は自前の xorshift32（再現的・シード可能）。**暗号用途ではありません**。
* `MAP` は整数割り算なので端数は切り捨て。入力レンジ**外**は外挿する（端で止めたいときは `CLAMP` と併用）。
* `MAP` で `inHi == inLo`（レンジ幅0）はゼロ除算 → `RESULT = 0` ＋ `STATUS` の `ERR_DIVZERO`。

## 反復と配列アクセス（v0.4.4）

> これらはポートではなく言語構文です。詳細は言語仕様書を参照。ここでは早見だけ。

**`REPEAT` / `ITR`** — `<N> -> REPEAT … END` で本体を N 回実行。`ITR` は本体内だけで有効な反復カウンタ（**1..N**・1始まり）。

**動的添字 `N -> SLOT`** — スロット名を裸で使うと実行時の添字でアクセスできる（`SLOT[k]` は定数専用）。**第1引数が添字（1始まり）**：

|形|意味|
|-|-|
|`N -> VAR`|リード `VAR[N-1]`（産出＝要素）。範囲外は `0`／空文字|
|`idx, val -> VAR`|ライト `VAR[idx-1] = val`（書いた値を産出）。範囲外は no-op|

- 対象: `VAR`/`GVAR`（int）・`SVAR`/`SGVAR`（str）は読み書き、`ARG`/`SARG` は読みのみ。
- 産出型はスロットの型なのでチェインに乗る（`ITR -> VAR -> STDOUT` 走査、`ITR, 式 -> VAR` 充填）。
- **`REPEAT` 内で `WAIT` は書けません**（コンパイルエラー）。REPEAT は 1 tick 内で完結する計算用。時間を空けたい反復は `ON <周期>` や self-post で。深い `N` は `ERR_BUDGET` で打ち切られることがあります。

```
# 配列を埋めて走査する
8 -> REPEAT
    ITR, RAND % 100 -> VAR       # VAR[ITR-1] = 0..99
END
0 -> GVAR[0]
8 -> REPEAT
    ITR -> VAR -> GVAR[1]        # v = VAR[ITR-1]
    GVAR[0] + GVAR[1] -> GVAR[0] # 合計
END
```

## メタ／動的ディスパッチ

|ポート|種別|説明|
|-|-|-|
|`INVOKER`|出力（可変引数）|第1引数の**文字列名のハンドラ**へ、残りの引数を渡して起動する|
|`HANDLER`|ハンドラ源|最初から1本だけ用意されているハンドラ（`-> HANDLER` で発火、`ON HANDLER … END` で受ける）|

```
# 文字列で指定したハンドラを動的に呼ぶ
"MYHANDLER", 1, 2, 3 -> INVOKER     # 次の tick で ON MYHANDLER が ARG[0..2]=1,2,3 で動く
```

* 名前が未登録、または対応する `ON …` が無い場合は**黙って無視**されます（遅延束縛）。
* これにより「応答コード→ハンドラ名」のようなジャンプテーブルや状態機械が書けます。

## チェインの例（実践）

`->` でポートを繋ぐと、途中結果（`RESULT`/`SRESULT`）が自動で次へ渡ります。
UART で受けた1行を整形してパースする典型例：

```
# RXLINE = "  send 0001 0002 ok  \r\n" のような1行だとして
RXLINE -> TRIMMER -> UPPER -> SGVAR[0]
# SGVAR[0] = "SEND 0001 0002 OK"

# 2番目のフィールドを取り出して16進数として読む
SGVAR[0], " ", 2 -> FIELD -> STRTOL
RESULT -> GVAR[0]                      # GVAR[0] = 1（"0001" を16進解釈）
```

> ヒント: 文字列を産出するポートの読み出しは、1つの引数リストにつき1個までです
> （複数を直接並べたいときは、いったんスロットに退避してから渡してください）。

## スクリプト内ポート（サブルーチン, v0.4.5）

`def_port` で「戻り値を返す自作ポート」＝**サブルーチン**を、C を書かずスクリプト内だけで定義できます。
組み込みの `FORMATTER` 等と**同格の関数ポート**として、`->` の両辺に置け・チェインできます。

- 宣言（冒頭一括）: `def_port(NAME, T_INT)` または `def_port(NAME, T_STR)`（戻り値の型）
- 本体: トップレベルに `PORT NAME … END` ブロックを書く
- 引数は `ARG` / `SARG` で受ける（`1, 3 -> SUM` なら `ARG[0]=1, ARG[1]=3`）
- **`ARG` / `SARG` / `VAR` / `SVAR` は全てポートの private ローカル**（v0.4.6）。VMが自動で退避/復帰し、`VAR`/`SVAR` は入口で 0/空にクリアされます＝**ポートは呼び出し元の作業変数を一切壊しません**（ライブラリ的に安全に使える）。共有され続けるのは `GVAR` / `SGVAR`（大域）だけ
- 戻り値は **`値 -> EXIT`**（`RESULT`/`SRESULT` に乗るのでそのままチェイン可）。`EXIT` されず `END` に達したら `0` / 空文字を返します

**制約**: 本体内で `WAIT` は不可（1 tick 内で完走）。**再帰は禁止**（自己・相互とも、ロード時に呼び出しグラフのサイクルとして検出＝ロードエラー）。

```
def_port(SUM,   T_INT)          # int を返すサブルーチン
def_port(GRADE, T_STR)          # str を返すサブルーチン

PORT SUM
    ARG[0] + ARG[1] -> EXIT
END

PORT GRADE                      # 点数 -> 評価文字（早期 EXIT）
    (ARG[0] >= 80) -> IFYES
        "A" -> EXIT
    END
    "B" -> EXIT
END

MAIN
    1, 3 -> SUM -> STDOUT              # 4（同期呼び → RESULT → 出力）
    95 -> GRADE -> SGVAR[0]           # "A"
    SGVAR[0] -> STDOUT
    1000 -> WAIT
END
```

> `EXIT` は v0.4.5 で `値 -> EXIT`（値を返す）に拡張されました。単独 `EXIT` は「戻り型の
> デフォルト値（`0` / 空文字）を返す略記」で、従来どおり書けます（後方互換）。ハンドラ内の
> `EXIT` は値を捨てて早期リターンします。

## ブロック局所エイリアス `def_local`（v0.4.6）

`VAR` / `SVAR` / `ARG` / `SARG` が何を指すかを、**そのブロック内でだけ有効な名前**にして可読性を上げます。
`def_alias`（大域・ファイル冒頭）の局所版で、`END` まで有効。純粋なコンパイル時マクロ（実行時コストゼロ）。

- 宣言位置: `INIT` / `MAIN` / `ON …` / `PORT …` の**冒頭**（本体の最初の文より前・一括）
- 対象: `VAR[n]` / `SVAR[n]`（読み書き可）、`ARG[k]` / `SARG[k]`（**読取専用**）、整数 / 文字列リテラル（読専）
- `GVAR` / `SGVAR`（大域スロット）は `def_local` 不可 → 大域は `def_alias` で
- 別ブロックで**同名を使い回せる**（局所ライフサイクル）。大域エイリアス名との衝突・同一ブロック二重宣言・文の後の宣言は `ERR_SYNTAX`

```
# 受信プロトコルの各位置に名前を付けて読みやすく
ON RXDATA
    def_local(SRC,  SARG[0])
    def_local(DST,  ARG[1])
    def_local(DATA, SARG[2])

    SRC, " ", DST, " ", DATA -> STDOUT
END
```

> `def_alias` = 大域（`GVAR`/`SGVAR`/リテラル・ファイル冒頭）、`def_local` = 局所
> （`VAR`/`SVAR`/`ARG`/`SARG`/リテラル・ブロック冒頭）。対象がきれいに分かれています。

## 時間を扱う（v0.4.7）

組み込みの本体は「時間をどう扱うか」です。Yajir には次の道具があります。

| やりたいこと | 書き方 |
|---|---|
| いま送る | `値リスト -> ハンドラ` |
| **N ms 後に送る** | **`値リスト -> ハンドラ AFTER <ms>`** |
| 周期的に | `ON <ms>` |
| **条件をまたいだ瞬間に** | **`ON <ms> (条件)`** |
| 自分を止めて待つ | `<ms> -> WAIT`（`INIT`/`MAIN` のみ） |

> **`MAIN` で `WAIT` を刻むのは最後の手段です。** `WAIT` はシステムを止めこそしませんが、
> **`MAIN` は1本しかない**ので、その時間軸を1つの処理が独占します（LEDとブザーを別パターンで
> 同時に、が破綻する）。しかも `WAIT` はハンドラでは使えません。
> **`MAIN`＋`WAIT` ＝ タイムライン1本 ／ 遅延post ＝ タイムラインN本**。

### 遅延post `値リスト -> ハンドラ AFTER <ms>`

**引数を持ったまま**、任意のハンドラを N ms 後に起動します。各ハンドラが「自分の続き」を予約して
自走できるので、独立した時間軸を好きなだけ並べられます。

```
CODE, POSITION -> MORSE_SYMBOL_END AFTER TONE_TIME   # TONE_TIME(ms) 後に起動
none -> KICKOFF AFTER 3000                            # 引数なしでもよい
```

- 遅延は **int の式**（変数・演算OK）。**`<= 0` は即post に縮退**します（エラーではありません）
- **ハンドラ源にだけ**付けられます（他の的に付けると `ERR_BAD_POSITION`）
- **文字列引数は post した瞬間にコピー**されます。満期までに元の `SVAR` が変わっても、届く値は post 時のもの
- **`INIT` からも予約できます**（t0 起点で解決＝起動 N ms 後に発火）。「起動してしばらくしてから開始」が書けます
- 満期後は普通の post と同じ経路（`ON <名前>` が走る）。**キャンセルはできません**
- 同時に待てる本数は `CFG_DELAY_SLOTS`（既定4）。溢れると新着を捨てて **`ERR_DELAY_FULL`** が立ちます

### 条件トリガ `ON <ms> (条件)`

周期的に条件を見て、**偽→真になった瞬間に1回だけ**発火します（エッジ）。条件が偽に落ちると
自動リセットされ、再び真になれば再発火します。

```
ON 10 (ADC0 > 30)        # 30 を超えた「瞬間」に1回
    "hot!" -> STDOUT
END

ON 10 (GPIO1 == 0)       # 外部からの 1->0 パルスで自動的に発火
    ...
END
```

- **グローバルのフラグが要りません**。手で書くと「条件 → フラグが0なら本体＋フラグを立てる／偽ならフラグを落とす」になるところが、ヘッダ1行で済みます
- **インターバルは必須**です（`ON (条件)` という形はありません）。ペリフェラル読みの頻度は書き手が握ります
- 条件は **int の純粋式**（`->` は式に書けないので副作用は入りません）。str は `ERR_TYPE_MISMATCH`
- **起動直後**: 条件が最初のポーリング時点で既に真なら、そこで1回発火します
- **ポーリング粒度は周期そのもの**。`ON 10` なら 10ms 毎にしか見ないので、**それより短いパルスは取りこぼします**

#### 応用: エラーハンドラ

`STATUS`（§エラー定数）自体がフラグなので、**フラグ変数を用意せずに**「エラーが立った瞬間だけ処理して落とす」が宣言的に書けます。**処理＝clear＝再武装**がそのまま噛み合います。

```
ON 10 (STATUS & ERR_DIVZERO)
    "! ERR_DIVZERO flagged -> clearing" -> STDOUT
    ERR_DIVZERO -> CLEAR_ERR
END
```

エラービットごとに1本書けば、**エラー別のハンドラ**になります。

> **`ON 10 (STATUS)` のような総括形は避けてください。** 別のビットが立っても `STATUS` は真のまま
> なのでエッジが立たず、2つ目のエラーを取りこぼします。**ビットごとに書く**のが正解です。

> 本体が自分のトリガ条件を落とした場合（上の `CLEAR_ERR` のように）、その場で再武装されます。
> なので clear した直後にまた同じエラーが起きても、次のポーリングできちんと拾えます。
