# Yajir（ヤジール） v0.4.7 仕様メモ

> 言語名: **Yajir**（ヤジール）。由来＝矢印（やじるし）＝ `->`。「野次る」の含意も込みで、攻めた設計が『それでも動く』ことを名に負う。
> ファイル拡張子: **`.yaj`**
> 対象: 超小型MCU（RAM 数KB〜数十KB / Arduino級）、ホストFWはC、既存ソースにマージして組み込む
> このメモはClaude Code実装の入力として書いている。確定事項／提案／未決を明示する。

### 変更履歴（v0.4.6 → v0.4.7）

**「時間軸」2点セット**——組み込みの本体は結局「時間をどう扱うか」であり、Yajir に足りなかった時間軸の道具を2つ揃える: **(1) 遅延post `AFTER`**（イベントを未来へ送る）と **(2) 条件トリガ `ON <周期> (条件)`**（状態の変化からイベントを作る）。どちらも新opcodeは0〜1個、RAM微増。

> 設計の背景: モールス送信のような時系列制御を「MAIN の中で `WAIT` を刻んで」書くのが最もやってほしくない筋。`WAIT` はシステムを止めこそしないが、**MAIN は1本しかない**ので、その時間軸を1つの処理が独占してしまう（LEDとブザーを別パターンで同時に、が破綻する）。しかも `WAIT` はハンドラで使えないのでイベント駆動と接続しない。**MAIN+WAIT＝タイムライン1本／遅延post＝タイムラインN本**。この2つは「時間軸を増やす／時間軸を生む」ための道具である。

**(2) 条件トリガ `ON <周期> (条件)`＝エッジ**（§6, §13）。§16 で「決定に必要なのは実使用感のみ」として保留していた項目を、実機の使用感（ADC しきい値・GPIO パルス検出）を得て**エッジで確定**。偽→真の瞬間に1回だけ発火し、偽で自動リセット、再成立で再発火。グローバルのフラグを1個も使わずに書け、可読性も上がる。旧 §16 の保留点だった「フラグ系条件のクリア作法」は、**エッジ採用により意味論に内包されて解決**（再発火には条件を一度落とす＝再武装が必要、というのがユーザー責務で正しい）。実装は**新opcode ゼロ**・`block_t` に `cond_start`+`prev` で **+64B**。詳細は §6。

**(1) 遅延post `値リスト -> ハンドラ AFTER <ms>`（引数を持ったままハンドラを N ms 後に起動）**（§10, §12, §13）。「あとで起きる」手段の表にあった**唯一の穴**を塞ぐ。

| 手段 | 遅延 | 引数 | 宛先 |
|---|:--:|:--:|---|
| `値リスト -> ハンドラ`（post） | ✗ 即時 | ✓ | 任意 |
| `ON <周期>` | ✓ 周期 | ✗ | 固定ブロック |
| `<ms> -> TIMER` | ✓ | **✗** | `ON TIMER` 1個だけ |
| `<ms> -> WAIT` | ✓ | — | MAIN/INIT のみ |
| **`値リスト -> ハンドラ AFTER <ms>`（v0.4.7）** | **✓** | **✓** | **任意** |

- **動機**: 実機（Pico 2 W のモールス送信）で、`TIMER` が引数も宛先も持てないため、遅延を**イベントキュー越しのビジーspin**（毎tick 自分を post し直して `NOW` をポーリング）で再発明せざるを得なかった。「N ms 後にこの状態でもう一度呼んで」が書けないことが根本原因。
- **なぜポートでなく構文か**（設計判断の記録）: 当初 `INVOKER` の遅延版ポート（`"NAME", ms, args… -> DELAY_INVOKER`）を検討したが、**ポートの入力は `argv` しかない**ため宛先も遅延も**ARG/SARG に詰める**しかなく、`CFG_ARG_COUNT=4` の**半分を配管が食う**。さらにハンドラ名は str なので **SARG を1枠消費＝`SARG_LEN × (1+CALL_NEST+QUEUE_LEN)` ＝ 672B（`SARG_LEN=32`）〜2.7KB（同128）**という桁違いのコストになる。`AFTER` なら**宛先はバイトコード1バイト（portidx）・遅延はスタック**で、**ARG/SARG を1枠も使わない**＋ハンドラ名のコンパイル時チェックも効く。よって1段上げて構文にする。
- **意味**: `expr_list` を評価して payload に、`AFTER` の式（int）を遅延msとして、`due = now + ms` で pending 表に積む。満期時に**通常のイベントキューへ enqueue**（＝以後は普通の post と完全に同じ経路・`ON <名前>` が走る）。**文字列引数は post 時にコピー**（満期までに元 `SVAR` が変わっても安全）。
- **`AFTER` はハンドラ源宛のみ**（他の的に付けたら `ERR_BAD_POSITION`）。**`AFTER <=0` は即post に縮退**（エラーにしない・正常な退化）。**キャンセルは無い**（`TIMER` と同様・最小に保つ）。同tickに複数満期したときの相互順序は未規定（§16 の「同tick混在イベントの順序」に合流）。
- **INIT フェーズは `TIMER` の作法**（v0.3.4 の `init_armed` と同じ）: INIT中に張った遅延postは**破棄せず t0 起点で解決**する。理由＝橋を閉じる目的は「**外来**イベントが凍結中に溜まって t0 でスタンピードするのを防ぐ」ことであり、遅延postは**スクリプト自身が書いた予約**だから。これにより **`INIT` からスクリプト定義ハンドラの起動を予約できる**（従来は post が破棄され `TIMER` は引数/宛先を持てないため書けなかった穴）:
  ```
  INIT
      … 初期化 …
      none -> KICKOFF AFTER 3000     // t0 から3秒後に ON KICKOFF
  END
  ```
- **資源**: pending 表 `CFG_DELAY_SLOTS`（既定 **4**）。1枠 ≈ `event_t + due + init_armed` ≈ **180B**（既定構成）→ +約720B。※`SARG_LEN=128` の実機構成では event_t が ~556B に膨らみ 4枠で **+2.2KB** になるので、実機は 2 枠へ絞るのが現実的（`SARG_COUNT × SARG_LEN` の乗数が効く箱がまた1つ増えた形・§12）。
- **満杯**: post 時に pending が満杯なら**新着を捨てて新STATUSビット `ERR_DELAY_FULL`(0x20)** を立てる（資源ごとに専用ビット、という既存の作法に一致）。失敗点は2箇所で切り分け可能——**post時の pending 満杯＝`ERR_DELAY_FULL`／満期時のキュー満杯＝既存 `ERR_QUEUE_OVF`**。
- 実装インパクト: 新opcode **`OP_POST_HANDLER_AFTER`**〈portidx, argc〉1個（遅延はスタック top から pop）＋文法1行（`send` に `[ "AFTER" expr ]`）＋vm に pending 表＋`sched_tick` に満期スキャン＋新定数 `CFG_DELAY_SLOTS`＋新STATUSビット `ERR_DELAY_FULL`。**遅延post は概念上 `TIMER` を包含する**（`TIMER`＝引数なし・宛先固定の遅延post）が、`TIMER` は既存互換のため据え置き。

### 変更履歴（v0.4.5 → v0.4.6）

**ブロック局所エイリアス `def_local`（ハンドラ/ポート/INIT/MAIN の冒頭で `VAR`/`SVAR`/`ARG`/`SARG` に名前を付ける）**（§3, §4, §13）。ハンドラやスクリプト内ポートが複雑になると `VAR[3]` / `SARG[2]` が何を指すか読めなくなる（セルオートマトン等が典型）。`def_alias`（v0.3.8・大域）が文脈依存ゆえ対象外にしていた `VAR`/`ARG` 系を、**ブロックスコープに限定すれば安全に名付けられる**——これを解禁する。実体は既存の字句マクロ＝**新opcode・新エラーコード・実行時コストすべてゼロ**。

- **`def_local(名前, 実体)` はブロック冒頭のみ・END まで局所**（`def_alias` が「ファイル冒頭・大域」なのと対をなす）。実体に書けるのは **`VAR[n]`/`SVAR[n]`（読み書き可）・`ARG[k]`/`SARG[k]`（読取専用＝受信専用）・整数/文字列リテラル（読専）**。文脈依存で大域に一意でないスロットは、局所スコープなら「このブロック内でだけこの意味」と嘘なく名付けられる。
- **役割分担（対象が排他的）**: `def_alias`＝`GVAR`/`SGVAR`/整数/文字列（大域・ファイル冒頭）／`def_local`＝`VAR`/`SVAR`/`ARG`/`SARG`/整数/文字列（局所・ブロック冒頭）。整数/文字列は双方で可。`def_local(X, GVAR[0])` のような**大域スロットは `def_local` 不可**（`ERR_SYNTAX`＝「それは `def_alias` で」）、逆に `def_alias(X, VAR[0])` も従来どおり不可。
- **利用可能ブロック**: `INIT`/`MAIN`/`ON …`/`PORT …` の**全ブロックの冒頭**（宣言は本体の最初の文より前・一括）。`ARG`/`SARG` を INIT/MAIN で別名にしても中身は空で無害。
- **衝突ルール**: (1) **別ブロック間の同名ローカルは許可**（END で捨てるので局所ライフサイクル・取り違えを誘発しない）。(2) **ローカル名が大域エイリアス名と衝突＝`ERR_SYNTAX`**（「ローカルのつもりが実は大域だった」事故を防ぐ）。(3) 予約語・スロット名・ポート名・同一ブロック内の二重宣言も `ERR_SYNTAX`（`def_alias` と同じ）。
- **実装**: `def_alias` のエイリアス表を **high-water-mark でスコープ化**するだけ——ブロック入口で表の位置を記録、冒頭 `def_local` を追記、`END` でその位置まで切り詰めて局所分を捨てる（`def_local` はトップレベルブロック冒頭のみでネストしない＝1ブロック1フラットスコープ）。展開先は既存の `LOAD_VAR`/`STORE_VAR`/`LOAD_SVAR`/`STORE_SSTR`/`LOAD_ARG`/`LOAD_SARG` に流すだけ（`ARG`/`SARG` への書き込みは既存 `ERR_BAD_POSITION`）。

例（受信プロトコルの各位置に名前を付けて読みやすく）:
```
ON RXDATA
    def_local(SRC,  SARG[0])
    def_local(DST,  ARG[1])
    def_local(DATA, SARG[2])

    SRC, " ", DST, " ", DATA -> STDOUT
END
```

**スクリプト内ポートの `VAR`/`SVAR` を private ローカル化（呼び出し元と独立）**（§3, §7）。v0.4.5 ではスクリプト内ポートは `ARG`/`SARG` だけを退避し、`VAR`/`SVAR` は呼び出し元と**共有**していた。しかしポートを「ライブラリ的」に使うと、内部で `VAR[0]` を作業に使っただけで呼び出し元の `VAR[0]` を破壊する footgun になり、致命的に使いづらい。そこで **`ARG`/`SARG` と同様に `VAR`/`SVAR` も呼び出しフレームに退避＋入口で 0/空クリア**し、戻り時に復帰する。これで **`ARG`/`SARG`/`VAR`/`SVAR` の4つが全てポートの private ローカル**になり、共有され続けるのは `GVAR`/`SGVAR`（大域）だけ＝教科書的な関数呼び出しモデルに揃う（`PORT` 内の `def_local(TMP, VAR[0])` も本当のローカル変数になる）。

- 実装は既存の `ARG`/`SARG` 退避と同じパターンの反復（`call_frame_t` に `save_var`/`save_svar` を追加・`OP_CALL_SCRIPT` で退避＋クリア・`OP_HALT` 復帰の3箇所）。新opcode/新文法なし。
- **RAM 増分**＝`CFG_CALL_NEST ×（CFG_VAR_COUNT×sizeof(value) + CFG_SVAR_COUNT×CFG_SSTR_LEN）`。int の `VAR` 退避は安価（数百B）、**`SVAR`（文字列バッファ）が支配項**（`SVAR_COUNT × SSTR_LEN × CALL_NEST`）。実際の最大呼び出し深度はロード時DFSで検算済ゆえ、**`CFG_CALL_NEST` を実深度まで絞ればRAMを直接削れる**（掛け算の係数）。文字列スロットの抜本テコ入れ（postキュー含む）と連動して効いてくる箇所。

### 変更履歴（v0.4.4 → v0.4.5）

**スクリプト内ポート定義 `PORT … END`（＝戻り値を返すサブルーチン）＋ `EXIT` を `値 -> EXIT` に統一**（§3, §4, §7, §11, §12, §13）。従来スクリプト内で書けるユーザー定義ブロックは `ON … END`（ハンドラ）だけで、これは次tick以降の**遅延評価・戻り値なし**だった。ここに**同期・値を返す**もう一系統＝**スクリプト内ポート**を足す。ユーザーから見れば要するに**サブルーチン**。ハンドラとポートの二系統が「遅延・戻り値なし・右辺専用」／「同期・戻り値あり・両辺可でチェイン可能」として対になる。

- **`PORT NAME … END`（スクリプト内ポート本体）＋ `def_port(NAME, T_INT|T_STR)`（冒頭宣言）**（§3）。`def_port` はコンパイラが解釈する3つ目の `def_`（`def_alias`／`def_handler` に続く）。宣言でポートを1本 `inout`・産出型付きで生やし、`PORT NAME … END` がその本体（バイトコード）を与える。**C実装のUtilityポート（`FORMATTER` 等）と同格の `inout` ポート**として振る舞い、`->` の**両辺に置け・チェインできる**（`1,3 -> SUM -> STDOUT`／`SUM -> VAR[0]`）。産出は既存の `RESULT`（int）／`SRESULT`（str）に乗るので**チェインも型チェックも既存機構がそのまま効く**（`1,3 -> SUM(int) -> SVAR[0]` は `ERR_TYPE_MISMATCH`）。
- **呼び出しルールの強い制約（実装を軽く保つ要）**：(1) **本体内で `WAIT` 禁止**（コンパイルエラー・`ERR_WAIT_IN_ON` を流用）＝`REPEAT` と同じ **within-tick**（呼び出しは決してtickをまたがない）。(2) **再帰禁止を静的DAG判定で一律に弾く**——スクリプト内ポート呼びは全てリテラルなポート名（動的ディスパッチ無し）ゆえ、**ロード末尾に呼び出しグラフのDFSを1回**回す。サイクルあり（自己再帰も相互再帰も同一経路）＝専用コード **`ERR_RECURSION`（`tok`＝サイクル上のポート名）**。同じDFSで**最長路＝最大コールスタック段数を算出**し、`CFG_CALL_NEST` 超過は既存 `ERR_NEST_TOO_DEEP`。実行時持ち越しは不要で、コールスタック溢れは静的に到達不能（実行時チェックは防御assertのみ）。(3) **`VAR`/`SVAR` は呼び出し元と共有**（退避しない＝サブルーチンの共有ワークエリア・私的ローカルは持たない）。**`ARG`/`SARG` はVMが自動退避/復帰する真の仮引数**（呼び出しで上書きされ、戻ると呼び出し元の値が復元される）。
- **`EXIT` を `値 -> EXIT`（値を戻すリターン文）に拡張＋単独 `EXIT` は略記として存続（後方互換）**（§7）。スクリプト内ポートでは `値 -> EXIT` で戻り値を `RESULT`/`SRESULT` に置いて呼び出し元へ返す（型は `def_port` 宣言と整合必須・`"x" -> EXIT` を `T_INT` ポートで書けば `ERR_TYPE_MISMATCH`）。ハンドラ（`ON … END`）内の `値 -> EXIT` は**値を捨てて**早期リターン。**単独 `EXIT` は「戻り型のデフォルト値を返す」略記**＝ハンドラ/`T_INT` ポートは `0 -> EXIT`、`T_STR` ポートは `"" -> EXIT` と同義（`END` 到達時のフォールスルーと完全に同一）。**`EXIT` されず `END` に達したら `0`（int）/空文字（str）を産出**。→ **既存スクリプトの裸 `EXIT`（`fib.yaj` 等）はそのまま通る＝破壊的変更なし**。
- **スクリプト内ポートを単独で左辺に置く**（`SUM -> X`・引数なしの値ソース読み）と、**引数オールゼロ・SARGオール空文字**で `PORT SUM … END` が呼ばれる（`ARG` を読む本体でも安全に0が入る）。**ポートからのハンドラ/TIMER呼び（`値 -> HANDLER`／`値 -> TIMER`）はOK**（非同期enqueue＝within-tickを壊さない・`WAIT` だけが禁止）。
- 実装インパクト: **VM初導入の同期呼び出し（戻り番地スタック）**が唯一の新概念。新opcode（`CALL_SCRIPT`〈portidx,argc〉／int戻り用 `STORE_RESULT`／`HALT` の文脈依存化 or `RET`）、**新エラーコードは `ERR_RECURSION`（サイクル・load時）1つのみ**（深度超過=`ERR_NEST_TOO_DEEP` を再利用）、新定数 `CFG_CALL_NEST`、port_t に `bc_start`、vm にコールフレーム配列（`ret_pc`＋`ARG`/`SARG` 退避）、コンパイラに**ロード末尾の呼び出しグラフDFS（サイクル検出＋最長路＝最大段数の静的検算）**。制約(1)(2)(3)により VAR/SVAR 退避もクロスtick永続化も実行時再帰チェックも不要で、負荷は v0.4.4 と同等〜やや上。

### 変更履歴（v0.4.3 → v0.4.4）

**有界ループ `REPEAT` ／ 反復カウンタ `ITR` ／ スロットの動的添字アクセス `N -> SLOT` の3点セット**（§3, §4, §7, §12, §13）。Yajir 初期の割り切り「ループ無し・添字は定数のみ」を、実用スクリプトが配列反復で壁に当たったため2つとも解く。安全性は既存の命令数バジェットと benign-0 縮退でほぼ据え置き（後方互換）。

- **`N -> REPEAT … END`（有界ループ）＋ `ITR`（反復カウンタ 1..N）**（§3, §7）。`<N> -> REPEAT` で本体を N 回実行。`ITR` は `REPEAT … END` 内だけで有効な読み取り専用の値源で、現在の反復回数 **1..N（1始まり）** を返す。N は**入口でスナップショット**（ループ中に元を変えても効かない）、`N ≤ 0` は0回。ネストは `CFG_LOOP_NEST=4` 段まで・`ITR` は**最内**を指す。ループ状態（カウンタ/上限/ITR）は vm のループフレームに持つ（オペランドスタックではない）。
  - **`REPEAT` 内で `WAIT` はコンパイルエラー（新 `ERR_WAIT_IN_LOOP`）**。これが設計の要：WAIT を禁じることで **`REPEAT` は「1 tick 内で完結し決してティックをまたがない within-tick 構造」**になり、ループ状態を yield またぎで永続化する必要も、MAIN の resume 時 sp リセットで壊れる問題も生じない。検出はコンパイラの `repeat_depth>0` フラグ1個（既存 `yield_ok` の隣）。**`TIMER` は許可**（yield せず「予約して継続」なので within-tick を壊さない）。
  - **暴走ガード＝バジェット**: 後退辺も1命令ずつ `CFG_INSTR_BUDGET` を消費し、超過時は **`END` の直後へ pc を飛ばして打ち切り**＋`STATUS` に新ビット **`ERR_BUDGET`**（中断点が常に文境界＝MAIN の resume も破綻しない・「途中で黙って止まった」を観測可能に）。挙動要約＝「**完走 or その場で打ち切り、いずれも同一tick内で決着**」。
  - **役割の線引き**: `REPEAT` は**同期・within-tick の計算用**（時間は進まない）。**時間を進めるペース配分は MAIN＋WAIT／`ON <周期>`／self-post 反復**で書く。深い/重い反復でタイミングを乱したくないなら self-post（1歩/tick・tick を専有しない）。深い `REPEAT` はその tick を最大バジェット分伸ばす＝ジッタ注意（クラッシュはしない）。
- **スロットの動的添字アクセス `N -> SLOT`（read）／`idx, val -> SLOT`（write）**（§4）。従来「添字は定数リテラルのみ」を、**スロット名を裸のポートとして使うと動的添字アクセスになる**形で解禁。**第1引数は常に添字（1始まり）**：`N -> VAR`（1引数）＝リード `VAR[N-1]` を産出／`idx, val -> VAR`（2引数）＝ライト `VAR[idx-1]=val` し**書いた値を産出**。**産出型はスロットの要素型**（int→`RESULT`／str→`SRESULT`）＝そのままチェインに乗る（`ITR -> VAR -> STDOUT` 走査・`ITR, 式 -> VAR` 充填）。**範囲外は benign**（リード=0/空文字・ライト=no-op＋0）でメモリ安全は実行時境界チェックが担保。**書く値の型は静的チェック維持**（`idx, "x" -> VAR` は `ERR_TYPE_MISMATCH`）。**`ARG`/`SARG` はリードのみ・ライトは `ERR_BAD_POSITION`**（受信専用の構造違反はコンパイル時に弾く）。**始点は1**（`ITR` の 1..N と整合。既存 `SLOT[k]` の0始まりとは別系統・docs明記）。
- 実装インパクト: 新opcode（`REPEAT_INIT`/`REPEAT_NEXT`/`LOAD_ITR`/`SLOT_INDEX`〈kind,argc〉程度）、新エラー `ERR_WAIT_IN_LOOP`（ロード時）・`ERR_BUDGET`（STATUS 実行時ビット）、新定数 `CFG_LOOP_NEST=4`、vm 構造体にループフレーム配列。言語の他部分・既存スクリプトへの影響なし。

### 変更履歴（v0.4.1 → v0.4.2）

**値の型を int / str の2択に純化する（内部 CHAR タグを撤去）＋ 文字リテラル `'A'` ＋ 変換Utility `CHR` の3点セット**（§2, §3, §5, §9, §10, §11）。

- **内部 `CHAR` 型を撤去し、値は int か str の2択に純化**（§9）。従来 VM 値は `int / char / str` の3タグ（`char`＝「.i に文字コードを持つ整数で、STDOUT はグリフ表示する」）だったが、`char` は**型というより「出力時のレンダリング指示が値に相乗りしているだけ」**で、実効は STDOUT の1分岐のみ。しかも `GVAR`（int スロット）を1回通るとタグは落ちる＝**直の `ARG[0] -> STDOUT` 一発しか生きない脆いタグ**で、実質「型」ではなかった。これを撤去し「**値は数か文字列。数を文字グリフとして描くかは出力側の仕事**」に整理する。撤去対象: 値タグ `SV_CHAR`／`val_char`／host STDOUT の char 分岐／`script_post_msg_char`・`SCRIPT_ARG_CHAR`（int 版と同義になるので薄い別名で残すか撤去）。UART RX 1バイトは**ただの int** として `ARG[0]` に入る。
- **文字リテラル `'A'` を字句として追加（＝整数リテラルの別表記）**（§2）。`0x41` や `65` と完全に同格の「整数の綴り違い」。`'A'` は int 値 65 を積むだけで、専用タグは持たない。ゆえに `'A' -> GVAR[0]`（int スロット）はOK、`(ARG[0] == 'A')` は素直な int 比較（`== 65` より可読）、`'A' + 1` は int 算術。`'A' -> SVAR[0]`（str スロット）は型違いで `ERR_TYPE_MISMATCH`。エスケープは文字列と同じ `'\r' '\n' '\t' '\\' '\''`。空 `''`・複数文字 `'AB'` は `ERR_SYNTAX`。実装は「トークナイザの字句＋push（int値として）＋ parse_primary の1分岐」で、新しい値タグや型は増えない。
- **変換Utility `CHR`（int→1文字str）を標準装備に追加**（§3）。CHAR タグ撤去で「数を文字グリフで出す」置き場が要るが、これは**出力側のポート**に持たせる＝ Yajir の「変換はポート」（`STRTOL`＝str→int の対）に一致。`65 -> CHR` → `SRESULT`=`"A"`。UART エコーは `ARG[0] -> CHR -> STDOUT` と書く（`FORMATTER "%c"` の一引数糖衣に相当。`FORMATTER` の `%c` は従来どおり int を受けてグリフ化するので温存）。
- **帰結（後方互換の注意）**: 旧イディオム `ARG[0] -> STDOUT`（受信文字のエコー）は、グリフではなく**10進数**を出すようになる。エコーは `ARG[0] -> CHR -> STDOUT`（または `"%c", ARG[0] -> FORMATTER -> STDOUT`）へ書き換える。1.0前ゆえ許容とするが破壊的変更として明記。得るもの＝型モデルが int/str の2択に純化・`'A'` が「整数の別表記」として一貫・変換が全部ポートに乗る世界観の統一。

**制御語 `EXIT` を追加（ON ハンドラの早期リターン）**（§3, §7, §13）。`ON … END` 内で、エラー条件等により**そのハンドラを途中で即終了**したいときに書く裸の制御語（`END`/`ELSE` と同じ制御語カテゴリ・`-> 送り先` を伴わない）。ネストした `IFYES` の内側からでもハンドラ**全体**を抜ける（C の `return` 相当・`break` のような一段だけの脱出ではない）。**`INIT`/`MAIN` 内では構文エラー**（`ERR_SYNTAX`）＝ON専用（`WAIT` の「ON不可」判定のちょうど逆で、`yield_ok` フラグで静的判別）。実装は**新opcode不要**——「その場で既存の `OP_HALT`（ブロック終端＝`EXEC_DONE`）を吐くだけ」で、ON ハンドラは yield せず走り切る（resume状態を持たない）ので早期HALTが安全に効く。コンパイラの `parse_stmt` 冒頭で横取り＋予約語1語追加のみ。

- **加工・合流は鎖の中では不可**（案ア確定）。`RESULT+1` の加工も `, 他値` の合流も禁止＝継ぎ目は常に**単一値を通す管**で分岐しない。必要なら鎖を切って複数文で書く。**帰結: 多引数は先頭段だけ**——継ぎ目以降は常に1値ゆえ、`FORMATTER`/`SLICER`/`EQUALS` 等の多引数Utilityは**鎖の先頭段**（先頭の `expr_list` から全引数をもらう）としてのみ機能（下流段に置くと1引数のみ・残り0埋め）。ここは救わない。

## 0. 設計思想（最重要）

**すべてはポート。プログラムは `値 -> ポート` で値をルーティングするだけ。**

GPIO、C関数、`WAIT`、`STDOUT`、`TIMER`、メッセージ送出先、条件分岐の制御フローまで、
あらゆる対象を「ポート」という単一概念に畳む。覚える文法カテゴリを極小化し、
書き手が楽に・楽しく書けることを最優先する。

この思想は省メモリとも一致する。`値 -> ポート` の1行1文はトークナイザが極小で済み、
UART流し込み＋数KB RAMという制約と正面から噛み合う。

設計ゴール:

- アプリ層ロジックをFW再ビルド/再フラッシュ無しで差し替え可能にする
- 割り込み（および各種非同期イベント）をスクリプトから簡単に扱える
- 暴走スクリプトがファーム本体をフリーズ・破壊しない

割り切りの基本姿勢: **なるべく軽量・シンプル。あきらめる所はスパッとあきらめ、複雑化する方向には持っていかない。**

## 1. 実行・統合モデル（確定）

- インタプリタ（C）を既存FWに**ソース統合**する。別バイナリにはしない。
- スクリプトは**UARTからテキストで受信** → **オンデバイスでコンパイル**（RAM上のコンパクトなバイトコードへ）→ **常駐実行**。
- スクリプトの寿命は **RAM常駐・揮発**（電源OFFで消える）。Flash/EEPROM永続化はv0では行わない。
- VMは**スタック型バイトコードVM**。**ヒープ不使用**、初期化時にアリーナ（固定RAM領域）を渡す。
- 実行は**協調スケジューリング**。ホストのメインループが `script_tick()` を周期的に呼ぶ。
- 各ハンドラ／MAINは**命令数バジェット内**で動かす。使い切ったら中断し状態を保持して次tickで再開。暴走してもメインループは回り続ける。

メインループの典型形:

```c
script_init(arena, sizeof(arena));
/* ... 各種 register / def ... */
while (1) {
    if (uart_block_ready())          /* スクリプト全文を受信したら */
        script_load(buf, len);       /* 受信→コンパイル→差し替え（失敗時はエラー返却） */
    script_tick();                   /* タイマ満期処理＋キュー処理＋周期/MAIN実行を1ステップ */
}
```

### 2フェーズ・ライフサイクル（確定）

起動から定常運転までを**2つのフェーズ**で定義する。`script_tick()` はフェーズで振る舞いを変える。

- **INITフェーズ（世界は凍結）**: `INIT` ブロックが排他的に完走する。`WAIT` 可（§7）。この間 `ON xxx` は発火せず（イベント・周期・`TIMER`満期すべて）、`MAIN` も回らず、周期タイマもカウントしない。`script_tick()` がするのは「INIT の WAIT を進める＋`NOW` を進める」だけ。イベントの橋は閉じる（§10）。
- **RUNフェーズ（始動）**: INIT を抜けた瞬間を **t0** とし、`MAIN` が回り始め、`ON` が live になり、周期タイマが t0 起点でカウント開始（§6）。INITで張った `TIMER` の締切も t0 起点で解決（§8）。

t0 という単一アンカーに時間系を全部ぶら下げる。`NOW`（get_tick）自体は INIT中も実時間で進む（WAITが動くため）が、**スケジューラの基準だけ t0 に固定**する。WAIT を使わない `INIT` は従来通り1tickで同期完了し、既存スクリプトの挙動は不変（能力が足されるだけ）。

## 2. 字句・基本構文（確定）

- **1行1文**。文の基本形は `式リスト -> ポート`。
- 行コメント `//`。
- ブロックは「ヘッダ行 … `END`」で囲む。インデント依存は**しない**（UART経由で空白/タブが化けるため、明示終端で安全側）。
- リテラル: 整数（`1000`、16進 `0xFFFE`、2進 `0b1010`、**文字 `'A'`**）、文字列（`"HELLO\r\n"`）、真偽は整数で代用（0=偽 / 非0=真）。
  - **文字リテラル `'A'` は整数リテラルの別表記**（v0.4.2）。`'A'` = そのASCIIコードの int（`'A'` == `0x41` == `65`）。専用の型は無く、`0x41` と完全に同格＝どこでも int として振る舞う（`'A' -> GVAR[0]` OK、`(ARG[0] == 'A')` は int 比較、`'A'+1` は int 算術、`'A' -> SVAR[0]` は型違いで `ERR_TYPE_MISMATCH`）。エスケープは文字列と同じ `'\r' '\n' '\t' '\\' '\''`。中身が空 `''`・2文字以上 `'AB'` は `ERR_SYNTAX`。「数を文字グリフとして出す」のは値ではなく出力側の仕事（`CHR`/`FORMATTER %c`・§3）。
  - 16進/2進の接頭辞・桁は大小文字どちらも可（`0xff` = `0XFF`）。数値中の `_` は桁区切りとして読み飛ばす（`0xFFFF_FFFF`, `1_000_000`）。8進は採らない。
  - `0xFFFFFFFF` は int32 のビットパターンとして格納（= -1 と同ビット。ビット演算で正しく振る舞う）。33bit以上はコンパイルエラー。
  - 文字列は **1バイト1文字・ASCII前提**（マルチバイトは将来、§16）。リテラル文字列はflash上・読み取り専用。動的生成は文字列スロット（§4）＋Utility（§3）で行う。
- 識別子（ポート名・予約語・スロット名）は**大文字推奨**。大文字小文字の区別有無はノブ（§16）。
- エスケープは `\r \n \t \\ \"` をサポート。

文の種類は実質2パターンに収束する:

1. `式リスト -> ポート`（値ルーティング文）
2. `ヘッダ … END`（ブロック）

## 3. ポート（確定）

ポートは方向で分類する。コンパイル時にC資源と束縛する。

| 種別 | 定義マクロ | 向き | 産出型 | 意味 |
|------|-----------|------|--------|------|
| 出力 | `def_out(NAME, c_func)` | 右辺のみ | none | `… -> NAME` でCの関数を呼ぶ（終端・値を受ける）。**戻り値を持たない** |
| 入力 | `def_in(NAME, c_func, 型)` | 左辺のみ | int/str **必須** | `NAME` を読むとCの取得関数を呼び、値を産む（値源） |
| 入出力 | `def_inout(NAME, c_func, 型)` | 両辺OK | int/str **必須** | 右辺で受け＋副作用、結果を `RESULT`/`SRESULT` に産出。**値を返す関数ポートはこれ**（チェイン中間に立てる唯一の種別・将来 §16） |
| 定数 | `def_const(NAME, value)` | 左辺(値) | int | 名前付き整数定数（しきい値・ピン番号等）。**システム提供**の定数用（ユーザーがスクリプト内で付ける名前は `def_alias`・下記） |
| ハンドラ源 | `def_handler(NAME)` | 右辺可(post先) | none | `ON NAME` で受ける源を宣言（§10）。`値 -> NAME` で self-post も可。`HANDLER` は起動時に自動registerされる既定インスタンス。**C側 `script_register_handler` の他、スクリプト側 `def_handler(NAME)` でも宣言可（v0.4.1・コンパイラが解釈・下記）** |
| スクリプト内ポート | `def_port(NAME, T_INT\|T_STR)` | 両辺OK | int/str **必須** | `PORT NAME … END` 本体を持つ**サブルーチン**（v0.4.5・§7）。C実装 `inout` と同格でチェイン可・`値 -> EXIT` で戻り値を `RESULT`/`SRESULT` へ返す。**同期・within-tick・再帰禁止・`WAIT` 不可・`ARG`/`SARG`/`VAR`/`SVAR` は全て private ローカル（自動退避/復帰・v0.4.6）・共有は `GVAR`/`SGVAR` のみ**。宣言＝冒頭一括・本体＝トップレベル `PORT` ブロック（コンパイラが解釈する3つ目の `def_`・下記） |

> 可変変数の定義（旧 `def_var`）は廃止。状態は固定スロット `GVAR/VAR`（§4）を使う。

#### `def_*` の位置づけ（確定）

- ポートの**実体はC側の `script_register_*` が唯一の真実**。スクリプト本文の `def_*` 行は**人間向けドキュメント**であり、コンパイラは解釈しない（書いても書かなくても・誤記でも動作は不変）。**ただし登録時に付与する属性（向き・産出型、下記）はコンパイラが使う**——属性は `def_*` テキストではなく `script_register_*` 呼び出しが運ぶ真実で、`->` の位置チェックと格納先の型チェックに用いる。
- 名前の照合は**登録済みポート表に対して**行う。未登録の名前を使用すると **`script_load` 時にコンパイルエラー**（`ERR_UNKNOWN_PORT`/`ERR_UNKNOWN_NAME`・行番号＋問題トークン `tok` 付き、§11）。これによりタイポは流し込み時に検出される（`NWO -> STDOUT` の `NWO` 等）。コアは候補サジェスト（did-you-mean）を出さず、`tok` と登録名の照合は表示側に委ねる（(B)方針）。
- `def_*` に記したがC側未登録のポートは、**実際に使用した箇所**で未定義エラーになる（使わなければエラーにもならない）。

#### ポート属性: 向き と 産出型（v0.3.8 確定）

ポートは**2つの独立した軸**で分類する。属性は登録（`script_register_*`）が運び、コンパイラが静的チェックに使う。

**(1) 向き軸**（スクリプト視点で `->` のどの位置に立てるか）

| 向き | `->`での位置 | 例 |
|------|-------------|----|
| `in`    | 左辺のみ（値源） | `READER`, `SENSOR`, `NOW`, `I2C1` |
| `out`   | 右辺のみ（終端・受けて即C実行・産出none） | `STDOUT`, `SYS_INIT`, `BUZZER`（書き専時） |
| `handler` | 右辺可（受けて即post・`ON`が後で走る・**チェイン終端のみ**・産出none） | `HANDLER`(既定), `RXDATA`, `MYHANDLER` |
| `inout` | 両辺OK（中間に立てる＝チェイン可・産出あり） | `LED1`（読み戻し可GPIO）, `FORMATTER`, `SLICER`, `WISUN`, 計算系 |

**(2) 産出型軸**（その的が**産み出す**値の型）。`int`（`RESULT` 経由）か `str`（`SRESULT` 経由）。

- **`out` と `handler` は産出none確定**＝産出型を持たない（指定そのものが存在しない・enumを受け取らない）。`out` は受けて即C実行、`handler` は受けてキューにpost（`ON`が後で走る）。どちらも値を次へ渡さない。
- **`in`・`inout` は産出型を必須で明示**。書き忘れはCビルドが通らず、産出型のすり抜けを防ぐ。
- str を産む的は値を `SRESULT` に置く（`script_set_sresult`）、int を産む的は `RESULT` に置く（`script_set_result` ／ 関数の戻り値）。

**判定できるようになること**（実行時コストゼロ・load時に確定）:

- 向き違反 → `ERR_BAD_POSITION`（§11）。`1 -> SENSOR`（in を右辺）、`LED1 -> VAR[0]`（out を左辺）、`… -> LED1 -> …`（産出noneのout/handlerを中間）。ハンドラ源（`HANDLER`等）も産出noneゆえチェイン**終端のみ**（中間不可）。
- 産出型違反 → 既存 `ERR_TYPE_MISMATCH`（§11）。`READER`（産出str）を `VAR[0]`（int スロット）へ、等。スロット代入の型違いと同じ違反として扱う。
- 例: `READER -> VAR[0]` は、`READER` の産出型が str と登録されていれば**load時に弾ける**（従来は産出型が無く int 暗黙仮定ですり抜けていた）。

**「読めるようにする」には昇格が要る**: `def_out` の的（書き専・例 `BUZZER`）を左辺で読みたいなら、glue側で `def_inout`＋産出型int に**実装し直す**（的のC実装に「現在値を `RESULT` に返す」処理を足す）。勝手には読めない＝書き専ポートの未定義読みが構造的に起きない。この昇格をすれば `1 -> BUZZER`（書く＋現在値を産出）`-> STDOUT`（受けて出す）のような tee 的使い方も、追加概念なしで inout だけで表現できる（`LED1` は最初から inout 宣言なのでそのまま tee 可）。

**ルーズ引数は不変**（§5）: 右辺で値を受ける側の左辺は従来どおり可変長・型自由・並び自由（`1, 2, 3 -> LED1` OK）。産出型は**産出する側**にのみ用い、受け側のルーズさは崩さない。

定義例（システムごとに異なる、コンパイル時に確定）:

```
def_inout(LED1, gpio_a1, int)     // GPIOへ書き＋現在値をRESULTへ産出（読み書き両対応）
def_out(SYS_INIT, init_system)    // void init_system(void)（終端・産出none）
def_in(I2C1, get_i2c1_val, int)   // int32 get_i2c1_val(void)（値源・int産出）
def_in(NOW, get_tick, int)        // int32 get_tick()  ※NOW=現在tick(ms)
def_out(STDOUT, my_print_f)       // UARTへ文字/数値書き出し（終端・産出none）
def_inout(VAL_CALC, my_calc, int) // 受けて計算しRESULTを産出＝関数ポート（inout）
def_in(READER, read_str, str)     // 文字列を産む値源。str産出はSRESULTへ（script_set_sresult）
def_const(HOT, 30)                // 名前付き定数
def_handler(UART1)                // UART1受信イベント
```

（注: 上の `int`/`str` は読みやすさ用の表記。C登録での enum は §11 の `script_type_t {SCRIPT_T_INT, SCRIPT_T_STR}`。`def_*` 行は非コンパイルのドキュメントなので表記は自由。）

#### 別名 `def_alias`（v0.3.8 確定・ユーザー定義の唯一の宣言）

`def_alias(名前, 実体)` は **`#define` 相当の純粋な字句マクロ**。コンパイラは名前を実体トークン列へ**展開してから通常処理する**。バイトコードに別名は残らず、新opcode・新エラーコードは無い。**実行時コスト厳密ゼロ**（別名表はコンパイル時のみ・固定長）。`script_register_*`（C側の真実）や `def_const`（システム提供の定数）と違い、`def_alias` は**スクリプト内で完結するユーザー定義**で、ロードごとに新スクリプトの宣言で総入れ替えされる。コンパイラが実際に解釈する `def_` は、この `def_alias` と `def_handler`（v0.4.1・スクリプト側宣言／後述）の2つ。

**実体に書けるのは3種**（いずれも実体が大域に一意に定まるもの）:

| 種 | 例 | 展開後 | 読み書き |
|----|----|--------|----------|
| (A) スロット | `def_alias(TRX_COUNTER, GVAR[6])` | `GVAR[6]` | 読み書き可（型はスロット継承: `GVAR`→int / `SGVAR`→str） |
| (B) 文字列リテラル | `def_alias(SEND_CMD, "SKSEND ...")` | `"SKSEND ..."` | 読専（str） |
| (C) 整数リテラル | `def_alias(MAX, 30)` | `30` | 読専（int） |

- **対象は `GVAR`/`SGVAR`（大域スロット）とリテラルのみ**。`VAR`/`ARG` は**別名にできない**——文脈依存（`VAR[0]`/`ARG[0]` はハンドラごとに別の意味）で実体が大域に一意でないため、名前が場所により違うものを指して嘘になる。原則: **別名の対象は実体が大域に一意なものに限る**。
- **別名は属性を持たず、展開後の対象がすべてを決める**。読み書き可否も型も位置も「展開後のトークン」に既存機構がそのまま効く（別名固有のルールはゼロ）。例: `x -> SEND_CMD` は展開後 `x -> "SKSEND ..."`＝文字列リテラルが左辺に来る → `ERR_BAD_POSITION`（read-only 専用判定は不要）。`123 -> COUNTER`（`SGVAR` 別名）は展開後に型分離（§4）が `ERR_TYPE_MISMATCH` を出す。
- **縛り**: 実体は素のスロット/リテラルのみ（`GVAR[i]`・`GVAR[6]+1` 等の式や添字変数は不可）。未定義の別名使用は `ERR_UNKNOWN_NAME`（§11）。別名と直書き（`TRX_COUNTER` と `GVAR[6]`）の混在は黙認（展開後同一）。
- **宣言はスクリプト冒頭に一括（義務）**。全 `def_alias` を本文（`INIT`/`MAIN`/`ON …`）より前にまとめる。読み手は冒頭が「語彙表」になり、コンパイラは別名表を本文コンパイル前に完成させてワンパスに入れる（前方参照不要）。冒頭ブロック以外に現れたら `ERR_SYNTAX`。

例（PERテストに当てた形・番号ずらしが冒頭1行で済む）:

```
def_alias(INTERVAL,    GVAR[0])     // (A) interval (ms)
def_alias(MAX_TX,      GVAR[5])     // (A)
def_alias(TRX_COUNTER, GVAR[6])     // (A) 6→7 にずらすなら此処1行だけ直す
def_alias(TPL_DATA,    "SKSEND 0 1002 0002 5 0102030405")  // (B) 文字列定数
def_alias(MAX,         30)          // (C) 数値定数

ON TIMER
    (TRX_COUNTER < MAX_TX) -> IFYES
        TPL_DATA -> HOSTCMD
        TRX_COUNTER + 1 -> TRX_COUNTER
        INTERVAL -> TIMER
    END
END
```

#### ブロック局所エイリアス `def_local`（v0.4.6 確定）

`def_local(名前, 実体)` は `def_alias` の**ブロックスコープ版**。`def_alias` が「ファイル冒頭・大域」なのに対し、`def_local` は**ブロック（`INIT`/`MAIN`/`ON …`/`PORT …`）の冒頭で宣言し、その `END` まで局所的に有効**。`def_alias` と同じく純粋な字句マクロ（展開後の対象がすべてを決める・**新opcode/新エラーコード/実行時コストすべてゼロ**）。

- **実体に書けるのは**（`def_alias` とは対象が排他的）:

| 種 | 例 | 読み書き |
|----|----|----------|
| `VAR[n]` / `SVAR[n]`（局所スロット） | `def_local(TMP, VAR[0])` | 読み書き可（型はスロット継承） |
| `ARG[k]` / `SARG[k]`（受信引数） | `def_local(SRC, SARG[0])` | **読取専用**（受信専用ゆえ書き込みは `ERR_BAD_POSITION`） |
| 整数 / 文字列リテラル | `def_local(HDR, "SKSEND")` | 読専 |

- **なぜ局所限定か**: `VAR`/`ARG` は文脈依存（`VAR[0]`/`ARG[0]` はブロックごとに別の意味）で大域に一意でないため `def_alias` の対象外だった。局所スコープなら「このブロック内でだけこの意味」と嘘なく名付けられる。よって **`def_local` の対象は `VAR`/`SVAR`/`ARG`/`SARG`＋リテラルのみ**——`GVAR`/`SGVAR` は大域なので `def_local(X, GVAR[0])` は `ERR_SYNTAX`（「それは `def_alias` で」）。
- **宣言位置**: そのブロックの**本体の最初の文より前に一括**（`def_alias` の冒頭一括と同じ流儀）。文の後に現れたら `ERR_SYNTAX`。`INIT`/`MAIN`/`ON`/`PORT` の全ブロックで使える（`ARG`/`SARG` を `INIT`/`MAIN` で別名にしても中身は空で無害）。
- **衝突ルール**:
  - **別ブロック間の同名ローカルは許可**。`END` で捨てるので局所ライフサイクル＝取り違えを誘発しない（`ON A` の `def_local(TMP, VAR[0])` と `ON B` の `def_local(TMP, SVAR[1])` は無関係）。
  - **ローカル名が大域エイリアス（`def_alias`）名と衝突＝`ERR_SYNTAX`**。「ローカルに入れたつもりが実は大域だった」という事故を防ぐ。
  - 予約語・スロット名・登録済みポート名・**同一ブロック内の二重宣言**も `ERR_SYNTAX`。
- **実装（high-water-mark スコープ）**: `def_alias` のエイリアス表を、ブロック入口で位置を記録 → 冒頭 `def_local` を追記 → 本体コンパイル → `END` でその位置まで切り詰めて局所分を捨てる。`def_local` はトップレベルブロック冒頭のみでネストしない（`IFYES`/`REPEAT` の中には書けない）＝1ブロック1フラットスコープ。展開先は既存の slot ロード/ストア命令にそのまま流す。

```
ON RXDATA
    def_local(SRC,  SARG[0])       // 受信の各位置に名前
    def_local(DST,  ARG[1])
    def_local(DATA, SARG[2])
    def_local(TMP,  VAR[0])        // 作業用スロットにも

    SRC, " ", DST, " ", DATA -> STDOUT
    DST + 1 -> TMP                 // VAR[0] へ書く（読み書き可）
END
```

#### スクリプト側 `def_handler`（v0.4.1 確定）

`def_handler(NAME)` は、`def_alias` に続き**コンパイラが実際に解釈する `def_`**。ハンドラ源は「**名前だけのイベントチャネル**」で束縛すべきCの実体（関数ポインタ/値）を持たないため、ポート種別の中で唯一スクリプト側から宣言できる（`def_in`/`def_out`/`def_inout` はC関数が必須ゆえ不可・引き続き非解釈ドキュメント）。

- **意味＝「このハンドラ源の存在を保証する（冪等）」**。C側が既に同名を `script_register_handler` 済みならば no-op（同種の再束縛）、未登録ならコンパイル時に新規登録する。以後 `ON NAME` と `値リスト -> NAME`（self-post, §10）が普通に解決される。
- **用途**: C を1行も書かずに、**スクリプト内だけで完結する名前付きハンドラ／状態機械**を作れる。`INVOKER`（文字列名での動的発火）や self-post 反復（§6）と組み合わせると、純スクリプトのイベント駆動ロジックが書ける。
- **後方互換**: 従来ドキュメントとして書かれていた `def_handler(UART1)`（C登録済み）等は、冪等ゆえ**挙動不変**。
- **構文・位置**: bare identifier（`def_handler(RETRY)`・クォート無し。既存 `def_*`／`def_alias` に一致）。宣言は使用より前＝**冒頭に一括**（`def_alias` と同様、前方参照不要のワンパス）。
- **衝突**: 予約語・スロット名・既登録の**非handler**ポートと同名は `ERR_SYNTAX`。**ポート表満杯**は `ERR_TOO_MANY_PORTS`（§11。従来 add_port 満杯時の「無言で登録失敗」をスクリプト経路では load エラーに格上げ）。

```
def_handler(RETRY)          // スクリプト側で新規ハンドラ源を宣言
def_alias(MAX, 3)

ON BTN
    3, 1000 -> RETRY        // self-post（次tickで ON RETRY）
END

ON RETRY
    ARG[0], ARG[1] -> STDOUT   // ARG[0]=3, ARG[1]=1000
END
```

#### スクリプト内ポート `def_port` / `PORT … END`（v0.4.5 確定）

`def_port(NAME, T_INT|T_STR)` は、`def_alias`・`def_handler` に続き**コンパイラが解釈する3つ目の `def_`**。宣言でポートを1本 **`inout`・産出型付き**で生やし、対応する**トップレベルの `PORT NAME … END` ブロック**がその本体（バイトコード）を与える。ユーザーから見れば**戻り値を返すサブルーチン**で、C実装のUtilityポート（`FORMATTER`/`SLICER` 等）と**完全に同格の `inout` ポート**として `->` の両辺に置け・チェインできる。

- **ハンドラとの対比**（二系統の役割分担）:

| | ハンドラ `ON … END` | スクリプト内ポート `PORT … END` |
|---|---|---|
| スクリプト側宣言 | `def_handler(NAME)` | `def_port(NAME, T_INT\|T_STR)` |
| 起動タイミング | **遅延**（次tick以降のディスパッチ） | **同期**（その場で呼ばれ、戻ってから続行） |
| 戻り値 | 無し | **有り（必須）**＝`RESULT`/`SRESULT` |
| `->` 位置 | 右辺のみ（post先・終端） | **両辺OK・チェイン可** |
| 発火源 | TIMER／周期／外部ISR／post | スクリプトからの呼び出し（`値 -> NAME`） |
| `WAIT` | 不可（`ERR_WAIT_IN_ON`） | 不可（同・within-tick） |
| 再帰 | 可（self-post＝非再帰の遅延） | **不可**（自己/相互とも load時の静的DAG判定で一律拒否・`ERR_RECURSION`） |

- **フレーム（private ローカル・v0.4.6）**:
  - **`ARG`/`SARG`/`VAR`/`SVAR` は全てポートの private ローカル**。VMが呼び出し時に caller の値を退避し、戻り時に復帰する。`ARG`/`SARG` は引数で充填（`1, 3 -> SUM` は `ARG[0]=1, ARG[1]=3`・str引数は `SARG[k]`）、`VAR`/`SVAR` は入口で 0/空にクリアされた真っさらな作業領域（**ポートは呼び出し元の `VAR`/`SVAR` を一切壊さない＝「ライブラリ的」に安全に使える真の関数**）。`PORT` 本体の `def_local(TMP, VAR[0])` はこれと相まって**本当のローカル変数**になる。
  - **共有され続けるのは `GVAR`/`SGVAR`（大域）だけ**。戻り値は `RESULT`/`SRESULT`。
  - **単独で左辺に置く**（`SUM -> VAR[0]`・引数なしの値ソース読み）と、**`ARG` オールゼロ・`SARG` オール空文字**で呼ばれる。
  - （v0.4.5 は `VAR`/`SVAR` を共有していたが、caller の作業変数を破壊する footgun ゆえ v0.4.6 で private 化。RAM増分＝`CFG_CALL_NEST ×（VAR＋SVAR退避）`で SVAR が支配項。実深度まで `CFG_CALL_NEST` を絞れば直接削れる。）
- **戻り値と `EXIT`**（§7）: 本体は `値 -> EXIT` で戻り値を返す。**値の型は `def_port` 宣言と整合必須**（`T_INT` ポートで `"x" -> EXIT` は `ERR_TYPE_MISMATCH`）。`EXIT` されず `END` へ達したら **`0`（int）/空文字（str）を産出**。
- **制約（within-tick を保つ）**:
  - **本体内 `WAIT` はコンパイルエラー**（`ERR_WAIT_IN_ON` を流用＝ハンドラと同じ「yield不可ブロック」）。呼び出しは決してtickをまたがない。
  - **`REPEAT`/`ITR`/`IFYES` は本体内で使用可**（`WAIT` が無いだけ）。
  - **`値 -> HANDLER`（self-post）／`値 -> TIMER`（予約）は本体内でOK**（非同期enqueueで即継続＝within-tickを壊さない）。
- **再帰の禁止（静的DAG判定・ロード時に一律）**:
  - スクリプト内ポート呼びは全て**リテラルなポート名**（動的ディスパッチ無し）ゆえ、**呼び出しグラフはロード完了時点で厳密に確定**する。各 `PORT` 本体をコンパイルする間に「本体→呼び先ポート」の辺を記録し（前方参照でも番号で辿れる）、**全ブロックのコンパイル後に DFS を1回**回す。
  - **サイクル検出 → 専用コード `ERR_RECURSION`（`tok`＝サイクル上のポート名）**。**自己再帰（1ノードの自己ループ）も相互/間接再帰（`A→B→A`）も同一経路で一律に弾く**（直接再帰の特別扱いは不要）。専用コード＋ポート名にするのは、意図しない多段サイクルで `ERR_SYNTAX`「構文エラー」とだけ出ても原因が分からないため（ホストは "recursion cycle at 'FOO'" 等と表示できる）。
  - 同じDFSで **`depth[node]=1+max(depth[子])` を計算＝最長路＝最大コールスタック段数**を算出。**`CFG_CALL_NEST` 超過は `ERR_NEST_TOO_DEEP`**（`IFYES`/`REPEAT` と同じネスト超過コードを再利用）。これがコールフレーム配列段数の**静的検算**になる。
  - 辺にするのは**同期呼び出し（`OP_CALL_SCRIPT`）のみ**。`値 -> HANDLER`／`値 -> TIMER`（非同期post・キュー越し）は辺にしない＝**ポートがpost経由でself-postループしても誤検出しない**（既存イディオムを温存・スタックを積まないので安全）。
  - 帰結: 新エラーコードは `ERR_RECURSION`（サイクル・load時）1つのみ、深度超過は既存 `ERR_NEST_TOO_DEEP` を再利用、実行時STATUSビットは追加しない。**実行時にコールスタックが溢れることは静的に到達不能**（実行時の深さチェックは防御assertのみ）。隣接情報はロード時のみの揮発メモリ（実行時RAM増分ゼロ）。
- **宣言はスクリプト冒頭に一括（義務）**、本体 `PORT … END` は他のトップレベルブロック（`INIT`/`MAIN`/`ON`）と並べて書く。`def_port` で宣言したが本体 `PORT` が無い／本体はあるが宣言が無い場合は load エラー。**衝突**（予約語・スロット名・既登録の非scriptポートと同名）は `ERR_SYNTAX`、**ポート表満杯**は `ERR_TOO_MANY_PORTS`。

```
def_port(SUM,   T_INT)          // int を返すサブルーチン
def_port(GREET, T_STR)          // str を返すサブルーチン

PORT SUM                        // ARG[0], ARG[1] を受けて和を返す
    ARG[0] + ARG[1] -> EXIT
END

PORT GREET                      // 名前(SARG[0]) を受けて挨拶文を返す
    "", SARG[0] -> EQUALS -> IFYES   // 空文字判定は EQUALS（== は int 専用・§9）
        "hello, world" -> EXIT  // 早期リターン（str）
    END
    "hello, ", SARG[0] -> MERGER -> EXIT
END

MAIN
    1, 3 -> SUM -> STDOUT              // 4（同期呼び→RESULT→STDOUT）
    "Yajir" -> GREET -> SGVAR[0]       // "hello, Yajir"
    SGVAR[0] -> STDOUT
    1000 -> WAIT
END
```

（`1, 3 -> SUM -> SVAR[0]` は `SUM` の産出が int・`SVAR` が str ゆえ `ERR_TYPE_MISMATCH`。`"return" -> EXIT` を `PORT SUM`〈T_INT〉内で書くのも同。)

### 予約ポート

| 名前 | 種別 | 動作 |
|------|------|------|
| `WAIT` | 制御 | `<ms> -> WAIT` で自分を中断（yield）。**INIT/MAIN で可**（`ON` は不可・§7） |
| `TIMER` | 制御 | `<ms> -> TIMER` でNms後に `ON TIMER` を1回予約（§8） |
| `IFYES` | 制御 | 直前の式が真なら続くブロックを実行（§7） |
| `EXIT` | 制御 | `値 -> EXIT`（v0.4.5拡張）。スクリプト内ポートでは戻り値を `RESULT`/`SRESULT` に置いて返す。ハンドラ内では値を捨てて早期リターン。**単独 `EXIT` は「戻り型のデフォルト値を返す」略記**（後方互換）。`INIT`/`MAIN` では構文エラー（§7） |
| `HANDLER` | ハンドラ源(既定) | 起動時に自動 `script_register_handler` される**既定のハンドラ源**（特殊機構なし・ユーザー定義のハンドラ源と同格）。`式リスト -> HANDLER` で自分宛に**即時1発post**（非再帰）、次tick以降 `ON HANDLER` を起動し、左→右の値が `ARG`/`SARG` に位置共有で充填（§6, §10） |
| `NOW` | 入力 | 現在tick(ms)。`def_in`で束縛する慣用名 |
| `STATUS` | 入力 | 異常フラグ集合（ビットフラグ）。`(STATUS & ERR_xxx) -> IFYES` で判定（§12） |
| `CLEAR_ERR` | 制御 | `ERR_xxx -> CLEAR_ERR` で該当ビットを明示クリア（§12） |
| `REPEAT` | 制御 | `<N> -> REPEAT … END` で本体を N 回実行（有界ループ, v0.4.4・§7）。本体内で `WAIT` 不可（`ERR_WAIT_IN_LOOP`）＝1 tick内で完結。超過はバジェットで打ち切り＋`ERR_BUDGET` |
| `ITR` | 入力(擬似) | `REPEAT … END` 内だけで有効な反復カウンタ（現在の回数 **1..N**・1始まり, v0.4.4）。読み取り専用・最内ループを指す |
| `AFTER` | 制御(修飾語) | `値リスト -> ハンドラ AFTER <ms>` で**遅延post**（v0.4.7・§10）。ポートではなく post 文の修飾語（`->` の右に立つ的ではない）。ハンドラ源宛のみ・`<=0` は即post。**予約語**なので別名/ポート名には使えない |

### 標準装備Utilityポート（文字列処理・確定）

文字列処理は「型」ではなく**標準装備のUtilityポート群**として提供する。言語コア（文法・VM）は不拡張で、中身はCの文字列関数を安全に通すだけ。どのシステムでもホストが必ず登録する組み込みポート（ユーザーの `def_out` とは別枠で最初から存在）。

文字列Utilityの**憲法**: 位置は**1始まり**、範囲は**(開始, 長さ)**。全Utilityでこの流儀に統一する（将来追加分も同様）。

返り値の型で戻り先が変わる: 文字列を返すUtility → `SRESULT`、数値を返すUtility → `RESULT`（§4）。

| Utility | 送信形 | 返り | 例 → 結果 |
|---------|--------|------|-----------|
| `SLICER` | `string, start, len -> SLICER` | `SRESULT` | `"HELLO, WORLD!", 3, 5` → `"LLO, "`（1始まり） |
| `MERGER` | `strA, strB -> MERGER` | `SRESULT` | `"NO MUSIC ", ", NO LIFE"` → `"NO MUSIC , NO LIFE"` |
| `COUNTER` | `string -> COUNTER` | `RESULT` | `"NO MUSIC "` → `8`（バイト長） |
| `FORMATTER` | `fmt, args… -> FORMATTER` | `SRESULT` | `"My name is %s, %d years old", "jiro", 25` → `"My name is jiro, 25 years old"` |
| `EQUALS` | `strA, strB -> EQUALS` | `RESULT` | 一致=`1` / 不一致=`0` |
| `CHR` | `int -> CHR` | `SRESULT` | `65` → `"A"`（int→1文字str, v0.4.2） |

- **`CHR`（v0.4.2）**: 整数を1文字の文字列に変換する（`STRTOL`＝str→int の対）。CHAR タグ撤去（§9）に伴い「数を文字グリフとして出す」を出力側ポートに持たせるための糖衣で、UART受信文字のエコーは `ARG[0] -> CHR -> STDOUT` と書く（`"%c", ARG[0] -> FORMATTER -> STDOUT` の一引数版に相当）。非表示コード等もそのまま1バイトの文字列にする。
- `FORMATTER` は可変arity＋引数の型タグで埋める。対応書式は **`%s %d %x %c %%` のみ**（`%f` は浮動小数点のため無し、`%n` は危険につき**禁止**）。`%c` は int を受けて文字グリフ1個を埋める（値タグに依存しない＝CHAR型撤去後も不変）。書式と引数の過不足は既存ルール（不足は空/0、過多は無視）。
- 生成文字列が固定長バッファを超えたら**切り詰め＋STATUSフラグ `ERR_STR_TRUNC`**（§12）。落とさず気づける。
- 文字列分岐は `EQUALS` 経由で書く（式の `==` は int 専用のまま。世界観を保つ）:

```
"ON", SVAR[0] -> EQUALS
(RESULT) -> IFYES
    1 -> RELAY
END
```

> 将来Utility（同じ流儀で追加）: `INDEXOF / REPLACE / UPPER / LOWER / TRIM` 等（§16）。

### 標準装備Utilityポート（数値処理・v0.4.3）

文字列版と対になる**数値ユーティリティ**（`register_mathutils()`）。すべて int産出（`RESULT`）。引数不足は0埋め（ルーズ）。

| Utility | 送信形 | 返り | 説明 |
|---------|--------|------|------|
| `RAND` | `RAND`（値源・引数なし） | `RESULT` | 非負乱数 `0..2^31-1`。範囲は `RAND % N`。自前 xorshift32（再現的・シード可能・非暗号） |
| `SEED` | `<seed> -> SEED` | none | 乱数を再シード（0は既定種へ）。ホストは `script_srand()` でも注入可 |
| `CLAMP` | `x, lo, hi -> CLAMP` | `RESULT` | `x` を `[lo,hi]` に飽和 |
| `MAP` | `x, inLo, inHi, outLo, outHi -> MAP` | `RESULT` | 線形リスケール（Arduino map）。int64中間・`inHi==inLo` は 0＋`ERR_DIVZERO`・レンジ外は外挿 |
| `MIN` / `MAX` | `a, b, … -> MIN` | `RESULT` | 可変長の最小/最大 |
| `ABS` | `x -> ABS` | `RESULT` | 絶対値（`INT32_MIN`→`INT32_MAX` 飽和） |

## 4. 変数スロット（確定）

事前の利用宣言はしない。**名称固定・要素数だけコンパイル時に確定**。役割を1スロット1つに分担する。

| スロット | 性質 | 用途 |
|---------|------|------|
| `GVAR[n]` | 永続・全体共有 | またいで保持したい状態（カウンタ・モード・フラグ） |
| `VAR[n]` | 揮発・スクラッチ | WAITを挟まない一連の計算の作業領域 |
| `ARG[n]` | 受信時に充填 | ハンドラのメッセージ引数（intビュー・型タグはpost側が決定。文字列ビューは `SARG`・位置共有、§10） |
| `RESULT` | 揮発・単一 | 直前の「関数ポート送信」の戻り値 |

ルール:

- **括弧添字 `SLOT[k]` は定数リテラルのみ**（`GVAR[0]`, `ARG[1]`・**0始まり**）。境界チェックがコンパイル時に完結し実行時コストゼロ（実体は番号付きレジスタ）。**可変（動的）添字は、スロット名を裸のポートとして使う別構文 `N -> SLOT` で提供する**（1始まり・実行時解決・下記「動的添字アクセス」, v0.4.4）。
- 各スロットの**要素数はコンパイル時定数**（ターゲットRAMに合わせ設定、§12）。
- ロード時に `GVAR/VAR` を0クリア。`RESULT` は未送信時0。

### VAR / GVAR / RESULT の生存規則（重要）

- `GVAR` … WAITまたぎ・ハンドラ間で**保持される**。
- `VAR` … **共有1本**。`ON` ハンドラは途中でyieldせず最後まで走り切るので、ハンドラ内では安全に使える。**MAINの `WAIT` をまたぐと保証しない**（待っている間に他ハンドラが踏み得る）。
- `RESULT` … 揮発。**次の関数ポート送信が来た瞬間に上書きされる**。「計算→直後に1回読む」が正しい使い方。

> 早見: WAITまたぎ／持ち越し→`GVAR`、WAITを挟まない作業領域→`VAR`、関数戻り値を直後に1回→`RESULT`。

### 文字列スロット（確定・案A）

動的文字列はヒープを使わず**固定長スロット**に置く。int版スロットと完全に対になる。

| スロット | 性質 | 用途 |
|---------|------|------|
| `SGVAR[n]` | 永続・全体共有 | またいで保持したい文字列（`GVAR` の文字列版） |
| `SVAR[n]` | 揮発・スクラッチ | 作業用文字列（`VAR` の文字列版） |
| `SARG[n]` | 受信時に充填 | ハンドラのメッセージ文字列引数（`ARG` の文字列版・位置共有・受信専用、§10） |
| `SRESULT` | 揮発・単一 | 文字列を返すUtilityの戻り先（`RESULT` の文字列版） |

- 各スロットは**固定長バッファ**。バッファ長と本数はコンパイル時定数（例: 64バイト×n本、§12）。
- 生存規則は int版と平行: `SVAR` は WAITまたぎ非保証（保持は `SGVAR`）、`SRESULT` は次の文字列Utility呼びで上書き。
- 書き込みがバッファ長を超えたら**切り詰め＋`ERR_STR_TRUNC`**（§12）。
- ロード時に文字列スロットは空文字でクリア。

### 動的添字アクセス `N -> SLOT`（確定・v0.4.4）

括弧添字 `SLOT[k]` が定数限定なのに対し、**スロット名を裸のポートとして使うと実行時に決まる添字**でアクセスできる。**第1引数は常に添字（1始まり）**：

| 形 | 意味 | 産出（＝スロットの型） |
|---|---|---|
| `N -> VAR`（1引数） | リード `VAR[N-1]` | 要素値（int）。範囲外→`0` |
| `idx, val -> VAR`（2引数） | ライト `VAR[idx-1] = val` | 書いた値（int）。範囲外→no-op＋`0` |
| `N -> SVAR` / `idx, str -> SVAR` | 同上・文字列版 | `SRESULT`（str） |

- **産出型はスロットの要素型**（`VAR`/`GVAR`=int→`RESULT`、`SVAR`/`SGVAR`=str→`SRESULT`）＝そのままチェインに乗る。`ITR -> VAR -> STDOUT`（走査）、`ITR, 式 -> VAR`（充填）。
- **チェイン位置**: リード（1引数）は継ぎ目（中間段）でも可、ライト（2引数）は継ぎ目が1値のため**先頭段専用**（§5 の「多引数は先頭段だけ」と整合）。
- **範囲外は benign**（リード=0/空文字、ライト=no-op＋0）。メモリ安全は VM の実行時境界チェックで担保＝コンパイル時保証を失う代わりに縮退0で受ける（「左辺ルーズ・止まらない」の精神）。**始点は1**（`ITR` の 1..N と整合。既存 `SLOT[k]` の0始まり／文字列Utilityの1始まりと同様の割り切りとして受容）。
- **書く値の型は静的チェック維持**: `idx, "x" -> VAR`（int スロットに str）は従来どおり `ERR_TYPE_MISMATCH`。添字だけが動的で、型検査はコンパイル時のまま。
- **対象スロット**: `VAR`/`GVAR`/`SVAR`/`SGVAR`（read+write）、`ARG`/`SARG`（**read のみ**・ライトは受信専用ゆえ `ERR_BAD_POSITION`＝定義上 read-only の構造違反をコンパイル時に弾く）。3引数以上は過多切り捨て、0引数は産出0。

#### 受信引数 `ARG` / `SARG`（位置共有・型ビュー, 確定）

受信メッセージは**型タグ付きの位置タプル**（§10）。`ARG[k]` と `SARG[k]` は、その同じ位置 k を**型で振り分けて読む2つのビュー**で、別カウンタではない。送信元=0 / 宛先=1 / データ=2 のように位置で並べ、各位置を合う型のスロット名で受ける（`ARG[0]`, `ARG[1]`, `SARG[2]`）。

| 位置 k の中身 | `ARG[k]`（intビュー） | `SARG[k]`（strビュー） |
|---|---|---|
| int タグ | その値 | `""`（空文字, benign） |
| str タグ | `0`（benign） | その文字列 |
| 位置なし（argc不足） | `0`（§5の0埋め） | `""` |

- 型不一致・不足は落とさず benign 値（`0` / 空文字）を返す（§5「不足は0埋め」の自然な延長）。書き手はプロトコルの位置ごとの型を知っているので、合う型で読むだけ。
- `ARG`/`SARG` は**受信専用**（dispatch時に充填・書き込み不可）。`SARG` の型分離は他の文字列スロットと平行（型はスロット名でコンパイル時判定）。ハンドラは走り切るので WAITまたぎ問題は生じない。

#### 文字列スロットは `->` の両辺に置ける（確定）

文字列スロットは int版スロットと同じく、`->` の送り元にも送り先にもなれる。次の4操作はすべて「文字列値を文字列スロットへstrcpy（切り詰めチェック付き）」という**単一の代入処理**で成立する:

```
"STRING"  -> SVAR[0]      // (1) リテラル代入
SVAR[0]   -> SVAR[1]      // (2) スロット間コピー（実質 strcpy）
SVAR[0]   -> COUNTER      // (3) 読み出して Utility へ
SRESULT   -> SGVAR[0]     // (4) Utility結果を保存
```

- 切り詰め: コピー先バッファが短ければ切り詰め＋`ERR_STR_TRUNC`（既存ルール）。
- 自己コピー `SVAR[0] -> SVAR[0]` は「同一なら何もしない」で安全処理（strcpyのundefinedを回避）。

#### 型の分離（確定）

- intスロット（`GVAR/VAR/ARG/RESULT`）と文字列スロット（`SGVAR/SVAR/SRESULT`）は**型が分離**。
- 型違いの代入（`"STRING" -> VAR[0]` や `123 -> SVAR[0]`）は**コンパイルエラー**。
- スロット名で型が判別できるため、チェックはコンパイル時に完結（実行時コストゼロ）。

```
"NO MUSIC ", ", NO LIFE" -> MERGER   // 結果は SRESULT へ
SRESULT -> STDOUT                     // "NO MUSIC , NO LIFE"
SRESULT -> SGVAR[0]                   // またいで保持したいなら永続スロットへコピー
```

### RESULT の更新規則

> `RESULT`/`SRESULT` が更新されるのは、`… -> PORT` の `PORT` が**値を産む的（産出型を持つ `inout`、§3）**のときだけ。int産出なら `RESULT`、str産出なら `SRESULT` にその結果が入る。
> 産出none の `out`（`STDOUT`/`LED1`書き等）、制御ポート（`IFYES`/`WAIT`/`TIMER`）への送信、`GVAR`/`VAR` への格納は `RESULT`/`SRESULT` を**触らない**。入力ポート（`in`）の読みは式へ直接値を出す（`RESULT` を経由しない）。

```
LED1, I2C1 -> VAL_CALCULATOR   // VAL_CALCULATORはinout(産出int) → RESULT = my_calc(LED1, I2C1)
(RESULT > 100) -> IFYES        // RESULTを読む→boolをIFYESへ（IFYES送信はRESULT不変）
    "YEAH!" -> STDOUT          // STDOUTはout(産出none) → RESULTは変えない（次の産出までRESULTは保持）
END
```

## 5. 複数引数の送信と arity 規則（確定）

送信文の左辺は**式のカンマ区切りリスト**にできる。左から評価してスタックに積み、`argc` 付きで対象ポートを呼ぶ。

```
LED1, I2C1 -> VAL_CALCULATOR    // my_calc(LED1, I2C1) を呼ぶ
```

全ポートに **arity**（受け取れる引数の数）があると考え、過不足を一律に正規化する:

- **供給過多 → あふれた分は切り捨て**
- **供給不足 → 不足分は暗黙の0で補う**

この規則は関数ポートに限らず全ポート共通。`A, B -> LED1` は `LED1 = A`（Bは切り捨て）になる。特別扱いは増えない。

評価順は**左→右で固定**（入力ポートのgetterに副作用があるときに効くので保証する）。

### 可変arityポート（確定）

固定arityの過多切り捨てに対する例外として、**可変arity（variadic）ポート**を認める。供給された**全引数を順に処理**する。代表は `STDOUT`:

```
"HELLO WORLD! ", 7777 -> STDOUT                         // 文字列＋数値を順に出力
"char + 10 is...", (VAR[0]+10), " ", VAR[0]+20 -> STDOUT // 各要素が式でよい
```

- 各要素は式（`VAR[0]+20` のように括弧なしでも可。`+` はカンマより強く結合）。
- 文字列と数値（int）が混在してよい。出力は値の型で決まる: **str値＝そのまま文字列出力／int値＝10進数**（v0.4.2で CHAR タグ撤去・§9。int を文字グリフで出したいときは `CHR`/`FORMATTER %c` で str 化してから STDOUT へ）。
- 可変arityはポート登録時の属性。`STDOUT` のような出力ストリーム系に限って付与し、通常ポートは固定arity（過多切り捨て）のまま。

### 普通の型付きC関数の接続（実装ガイド）

内部ABIは `(argc, argv)` 一本に統一し、普通のC関数はマクロで薄いアダプタ（thunk）を生成する。切り捨ては自動、0埋めは三項で実現:

```c
/* 内部ABIは (int argc, const int32_t *argv) 一本 */
#define DEF_OUT2(PORT, FN)                                  \
    static void PORT##_thunk(int argc, const int32_t *a){   \
        (void)argc;                                         \
        int32_t r = FN(argc>0?a[0]:0, argc>1?a[1]:0);       \
        script_set_result(r);                               \
    }
/* 値を返す＝inout（産出int）。登録: script_register_inout("VAL_CALCULATOR", VAL_CALCULATOR_thunk, SCRIPT_T_INT); */
```

登録時に arity が分かるので、コンパイラで「明らかな引数過不足」を**警告**に出すことは可能（ルール上はエラーにせず黙って正規化）。

### パイプライン・チェイン `A -> F1 -> F2`（v0.4 確定）

1行に `->` を複数連ねると、**前段の産出値（`RESULT`/`SRESULT`）を次段へそのまま流す**パイプラインになる。これは新しい実行モデルではなく、**複数文への純粋なコンパイル時糖衣（desugaring）**。`->` は値を返す演算子に**ならない**——ポートは終端のままで、「1文1射」がN個並ぶのと実行時は完全同一。**案ア（純パイプ）に確定**: 継ぎ目を流れるのは前段の産出値**そのまま**だけ。`RESULT+1` の加工も `, 他値` の合流も鎖の中では不可（必要なら鎖を切って複数文に分ける）。継ぎ目は常に単一値を通す管で分岐しない。

#### 段の役割と位置規則（属性表を引くだけ・load時静的・実行時ゼロ）

| 段 | 立てられる種別 | 受け取る値 | 違反 |
|----|----------------|------------|------|
| 先頭 H | `expr_list`（in読み／スロット／リテラル／`RESULT`/`SRESULT`…） | 通常の左辺そのまま（多値OK） | `in` を右辺(2段目以降)へ → `ERR_BAD_POSITION` |
| 中間 Si | **`inout` のみ**（産出ありの関数ポート） | 左の継ぎ目から **1値** | `out`/`handler`/`in`/スロット書き を中間へ → `ERR_BAD_POSITION` |
| 終端 T | `out` / `inout` / `handler` / 制御(`IFYES`/`WAIT`/`TIMER`) / 書込可スロット(`GVAR`/`VAR`/`SGVAR`/`SVAR`) | 左の継ぎ目から **1値** | 終端スロットの型違い → `ERR_TYPE_MISMATCH` |

- `out`/`handler` は**産出none**（§3）ゆえ次段へ渡す値が無い＝**中間に立てられない・終端のみ**。これが「産出noneは中間不可」の実体。
- 終端が `IFYES` なら通常どおりブロックを開く（`<前段産出> -> IFYES` ＝ `(産出値) -> IFYES`、§7）。`TIMER`/`WAIT` 終端は `<前段産出> -> TIMER`（Nms予約）等として働く。
- 終端が `handler` なら加工結果をイベントとして即post（self-post・§10）。`"%x", N -> FORMATTER -> MYHANDLER` のように「組み立てた文字列を投げる」が書ける。

#### 継ぎ目の型（産出型属性で決定・継ぎ目はルーズ）

- 各継ぎ目で `RESULT`(int) と `SRESULT`(str) のどちらを流すかは、**直前段の産出型属性**（§3 の `script_register_*` が運ぶ真実）が一意に決める。int産出→`RESULT`、str産出→`SRESULT`。
- **継ぎ目では型チェックしない**。受け側はルーズ（§5・入力期待型を持たない）ので、前段が str を出して次段が int で読んでも、§4 の benign 値（`0`/空文字）で受けるだけ＝**おかしな結果が出るだけで破綻しない**。鎖の途中で int→str→int と型が変わってよい。
- 型チェックが入るのは**終端がスロット**のときだけ＝既存の型分離（§4・`ERR_TYPE_MISMATCH`）がそのまま効く（`… -> FORMATTER -> VAR[0]` は str産出を int スロットへ＝型違い）。

#### 展開（desugaring）アルゴリズム（実装ガイド）

パーサは送信文を `expr_list "->" PORT { "->" PORT }` として読む。`->` が2個以上なら鎖。展開は次のとおり（新opcode不要・既存の `CALL_OUT(argc)`/`LOAD_SLOT`/`STORE_SLOT`/`PUSH` のみ）:

1. 先頭セグメント `expr_list -> S1` を通常どおりコンパイル（左→右で評価して積み、`S1` を argc 付きで呼ぶ）。
2. 2段目以降の各 `-> Si`（i≥2）について:
   - 直前段 `Si-1` の登録属性を引き、**産出型が int なら `RESULT`、str なら `SRESULT`** を暗黙の左辺として1個 LOAD（argc=1）。
   - `Si` を呼ぶ。中間段なら `Si` は `inout` 確定。終端段はスロットなら `STORE_SLOT`（型一致チェック）、制御(`IFYES` 等)なら該当処理、それ以外は `CALL_OUT`。
3. 位置チェック（登録表を引くだけ・実行時ゼロ）:
   - 中間段（最後でない `Si`）が `inout` 以外 → `ERR_BAD_POSITION`。
   - `in` が右辺（2段目以降）→ `ERR_BAD_POSITION`。
   - 終端がスロットで産出値の型と不一致 → `ERR_TYPE_MISMATCH`。
   - 「前段が産出none(out/handler)なのに次段がある」は、その産出none段が中間に居る状況なので上の中間チェックで自動的に `ERR_BAD_POSITION` に落ちる（別判定不要）。
4. エラーの `line` は鎖の行番号、`tok` は問題セグメントのポート名（§11）。

**`RESULT`/`SRESULT` 上書きの安全性**: 各継ぎ目は「**LOAD（前段の産出を読む）→ CALL（次段が新たな産出を書く）**」の順なので、読んでから上書きで安全。スタックVMの `PUSH`/`LOAD` → `CALL_OUT` という自然な順序がそのまま正しさを保証する（特別な退避は不要）。

#### 主用途（パターン）

```
// 判定の連鎖（終端=IFYES）。EQUALS産出int → RESULT → IFYES
"ON", SVAR[0] -> EQUALS -> IFYES
    1 -> RELAY
END

// 送信フロー（str→int を跨ぐ）。FORMATTER産出str → SRESULT → WISUN産出int → RESULT → IFYES
"snd %x", CODE -> FORMATTER -> WISUN -> IFYES
    "sent." -> STDOUT
END

// 計算して即格納（終端=スロット）。VAL_CALC産出int → GVAR[0]
LED1, I2C1 -> VAL_CALC -> GVAR[0]

// 加工して self-post（終端=handler）。FORMATTER産出str → SRESULT → MYHANDLER
"%x", N -> FORMATTER -> MYHANDLER
```

各鎖は右の複数文版と**同一バイトコード・同一挙動**になる（例: 1本目は `"ON",SVAR[0] -> EQUALS` / `(RESULT) -> IFYES` と等価）。

## 6. ブロックとトリガ（確定 / 一部提案）

### 予約ブロック

```
INIT          // 起動直後に一度だけ実行（WAIT可・完走まで世界は凍結, §1）
    none -> SYS_INIT
END

MAIN          // 自動で繰り返し実行（協調ループ。WAIT可）
    1000 -> WAIT
    1 -> LED1
    1000 -> WAIT
    0 -> LED1
END
```

- `INIT` は1回。`MAIN` は繰り返し。`none` は「引数なしの起動」を表す予約値（argc=0で関数ポートを叩く）。
- **起動基準は t0（INIT脱出時刻）**（§1）。周期 `ON <ms>` の**初回満期は t0 起点**（「起動から」ではなく「INIT脱出から」Nms後）。ゆえに INIT 内で長く `WAIT` しても、その待ち時間は周期の取りこぼし（catch-up債務）を生まない——長い INIT が t0直後の catch-upバーストを引き起こさない。

### `ON <源>` トリガ（確定）

源が発火したら対応ブロックを実行する汎用イベント束縛。**割り込みもメッセージも周期もタイマも同じ形**で吸収する:

```
ON 1000        // 周期: 1000msごと（時間源）
    "HELLO WORLD!\r\n" -> STDOUT
    I2C1 -> STDOUT
END

ON UART1       // ハンドラ源（def_handlerで宣言・C側/スクリプト両方からpost可）
    ARG[0] -> STDOUT
END

ON HANDLER     // 既定のハンドラ源（起動時に自動register・式リスト -> HANDLER で即時post・非再帰, §10）
    ARG[0] -> STDOUT
END

ON TIMER       // ワンショットタイマ満期（§8）
    0 -> BUZZER
END
```

- ハンドラ引数は `ARG[]`（int）/`SARG[]`（str）の位置共有ビュー。各位置の型タグはpost側＝Cグルーが決める（§4, §10）。
- **`ON` ハンドラ内では `WAIT` 禁止（コンパイルエラー）**。`INIT`/`MAIN` は yield可能（§7参照）。

### 同一tickでの実行順序（確定）

- 同一tickで複数の**周期ハンドラ**（`ON <数値>`）が満期した場合、**ハンドラの定義順（ソース出現順）で実行する**。これは保証する挙動とする（スケジューラ最適化時もこの順序を壊さない）。
- 周期ハンドラ／`TIMER`満期／非同期post が同tickに混在する場合の**相互順序はv0では未規定**（§16で扱う。実機では外部post優先などのポリシーを後日確定）。

### 周期ハンドラの満期ポリシー（確定）

大きな処理遅延で `script_tick()` の間隔が空き、周期満期が複数回パスされたときの扱い。**回数の意味論**が用途で割れるため、明示的に決める。

- **catch-up（既定）**: パスした回数ぶんハンドラを呼ぶ。取り戻しは**以降のtickに1回ずつ分散**し、同tickでまとめて連発しない（高負荷時に発火が雪だるま化するのを避ける）。「呼ばれた回数が資産」（積算カウンタ等）のカジュアル用途に素直。
- **coalesce（コンパイルオプション）**: 何周パスしても気づいた時点で実質1回に丸め、次回満期を現在基準で張り直す。「最新状態だけが意味を持つ」用途（表示更新・制御出力）や、取り戻し発火を嫌う場面向け。

> 方針: 精密なタイミングを要する処理はそもそもスクリプト化しない、という前提のもとカジュアルさを優先し、既定をcatch-upとする。精度や非取り戻しが要る稀なケースはビルド時にcoalesceへ切替。
>
> 切替は**コンパイルオプション（ビルド単位の全体設定）**。将来、ハンドラ個別修飾（例 `ON 1000 LATEST`）を足す余地は§16に残す。

検証結果（§14の検証サンプル）: 初回に意地悪ブロッキングで550ms居座らせ5回ぶんパスさせると、1秒地点のカウンタが catch-up=10 / coalesce=6（差4=パス回収ぶん）となり、両ポリシーの差が観測できる。これを回帰基準とする。

### `ON <周期> (条件)` 条件トリガ（確定・**エッジ**, v0.4.7）

周期タイミングで条件を見て、**偽→真の立ち上がりで1回だけ**発火するトリガ。**インターバル指定を必須**とする（`ON (条件)` 単体は作らない）。ペリフェラル読み取り（I2C/SPI/ADC）は時間・バス占有・電力のコストがあるため、評価頻度を書き手が必ず握れるようにする。

```
ON 10 (ADC0 > 30)     // 10msごとに評価。30を超えた「瞬間」に1回だけ発火
    "hot!" -> STDOUT
END

ON 10 (GPIO1 == 0)    // 外部からの 1->0 パルスで自動的に発火（10ms粒度）
    ...
END
```

- **エッジ意味論（確定）**: 各満期で条件を評価し、**前回偽・今回真**のときだけ本体を実行する。**条件が偽になった時点で自動リセット**され、再び真になれば再発火する。「前回真偽」は `block_t` の1bit（`prev`）に持つ。
- **等価な手書きコードを置き換える**（グローバルのフラグを1個も使わずに済む）:
  ```
  ON 10                          //  ↓これと等価。ON 10 (ADC0>30) なら1行で済む
      (ADC0 > 30) -> IFYES
          (GVAR[0] == 0) -> IFYES
              // something
              1 -> GVAR[0]
          END
      ELSE
          0 -> GVAR[0]
      END
  END
  ```
- **フラグ系条件のクリア作法**（旧 §16 の保留点）は、エッジ採用により**意味論に内包されて解決**した。`ON 10 (GVAR[0] == 1)` は立ち上がりで1回だけ走り、**再発火には条件を一度落とす（＝フラグを clear して再武装する）必要がある**——これはユーザー責務で正しい。
- **`prev` は「本体が走った後」の条件値**（確定・v0.4.7）。本体が**自分のトリガ条件を落とす**「フラグ消費型」——下記のエラーハンドラが典型——で、**clear をそのまま再武装として扱う**ため。走る前の値を入れると、*clear 直後・次の満期より前に条件が再成立したとき* `prev` が真のままとなり、**以後永久に発火しなくなる**（実装時に踏んだ。テスト `7b` が回帰ガード）。再評価は**発火したときだけ**なので、エッジが稀である以上コストは無視できる（本体が条件に触らない普通の条件では同じ値になるだけ＝挙動不変）。
- **応用: STATUS のエラーハンドラ**（`STATUS` 自体がフラグなので、フラグ変数を用意する必要すら無い）:
  ```
  ON 10 (STATUS & ERR_DIVZERO)
      "! ERR_DIVZERO flagged -> clearing" -> STDOUT
      ERR_DIVZERO -> CLEAR_ERR          // 処理＝clear＝再武装
  END
  ```
  「立ったら1回だけ処理して落とす」が宣言的に書ける。エラービットごとに1本ずつ書けば**エラー別ハンドラ**になる。※`ON 10 (STATUS)` のような**総括形は非推奨**——別のビットが立っても `STATUS` は真のままなのでエッジが立たず、2つ目のエラーを取りこぼす。**ビットごとに書く**こと。
- **t0 の挙動**: `prev` はロード時 false から始まる。INITフェーズ中はハンドラを発火しない（既存の言語仕様＝橋が閉じている, §1/§10）。t0 で周期の初回満期が張られ（`next_time = t0 + 周期`）、**そこで条件が既に真なら「偽→真」＝立ち上がりとみなして発火**する。つまり「MAIN に入って条件が成立していればすぐ呼ばれる」が、特別扱いなしで自然に成立する。
- 条件は**副作用のない純粋式に限る**（int比較・論理・ビット演算）。`->` は式の文法に含まれないので、`-> Utility` 等はそもそも書けない＝**純粋性は文法が保証**する。※スクリプト内ポートの値源読み（`(SUM > 30)`）は文法上は書けてしまう（within-tick で安全ではある）が、**条件は純粋式で書くのが原則**。
- **条件の型は int 必須**（str は `ERR_TYPE_MISMATCH`）。`ON GVAR[0] == 1` のように入力ポートだけでなく変数スロットの純粋式も可（状態機械のステート遷移検出に有用）。
- **ポーリング粒度は周期そのもの**。`ON 10` なら 10ms 毎にしか見ないので、**それより短いパルスは取りこぼす**（仕様）。粒度と負荷のトレードオフは書き手が周期で握る。
- **catch-up との関係**: 条件付き周期では**取りこぼし消化（catch-up）は無意味**（本質は回数ではなくエッジ）。満期を取りこぼしても、次のポーリングでエッジを拾うだけ。
- 実装（**新opcode ゼロ**）: コンパイラは条件式を**独立チャンク**として本体より前に吐く（`cond_start: <式> HALT` / `bc_start: <本体> HALT`）。スケジューラは満期時に `cond_start` から `vm_exec` して**スタック先頭の真偽**を読み、`cond && !prev` なら `run_handler`、最後に `prev = cond`。`block_t` に `cond_start`(2B)＋`prev`(1B) を足すだけ（`20B→24B` × `CFG_MAX_BLOCKS` ＝ **+64B**）。新エラーコードも新STATUSビットも不要。
  - 設計メモ: 「コンパイル時糖衣で desugar する」案も検討したが、`prev` を置く**隠しフラグ**が必要で、隠し `GVAR` は取れず、隠しビットを触るには**新opcodeが要る**＝糖衣の方が高くつく。スケジューラで持つのが最安、という逆転が起きたためこの形にした。

### self-post による反復（確定イディオム）

任意長配列を採らない（§0）帰結として、`for`/`REPEAT` は採らない。代わりに**ハンドラ源への self-post で反復を書く**のが正準形（既定の `HANDLER`、または `def_handler` で作った任意の源。全ハンドラ源が `->` の右辺に立てて self-post できる、§10）。

```
ON HANDLER
    (ARG[0] > 0) -> IFYES
        // do something（ARG[0] を使った1ステップ分の処理）
        ARG[0] - 1 -> HANDLER     // 次の1ステップを予約（カウンタを1減らして自分へ）
    END
END
```

- これは**本物の再帰ではない**。`ARG[0]-1 -> HANDLER` は §10 経路に1発積んで**即return**し、その行で `ON HANDLER` 本体へ降りない。次tick以降のディスパッチで改めて回る（`TIMER` 張りと同じ「予約して即return」）。
- ゆえに**スタックを積まない**（深さN でも段が増えない・`ARG[0]=10000` でも安全）。一方で**1反復＝最低1ディスパッチ**（密なループ用ではなく「状態機械を1段ずつ進める」感覚）。回している間キューを1枠占有する。
- 状態は `ARG`/`SARG` で持ち回る（多値可）。WAITをまたがないので `VAR`/`SVAR` を作業に使える。またいで残すものは `GVAR`/`SGVAR`。

### self-post の世代展開（幅優先・確定）

1回の `ON HANDLER` 実行が複数の子を self-post すると、反復は枝分かれして**ツリー展開**になる。この展開順は**幅優先（BFS）で確定**する。`script_tick` の処理単位が「1世代（generation）」だからである（drain規則は§10）。

- **`script_tick` 1回＝1世代**。tick開始時点でキューにあった要素（＝BFSの同一フロンティア）をそのtickで全件処理し、drain中に積まれた子（次世代）は**次tickへ繰り越す**。FIFO＋この世代drainの構造的帰結として、**世代境界＝tick境界**になる。
- **兄弟順は文の出現順**。同一ハンドラ本体内の複数 `-> HANDLER` は、本体を上から実行し当たるたびに即 enqueue するので、**ソース上の出現順**でキューに並ぶ（§5の「1文内の引数を左→右評価」とは別レイヤー＝文をまたいだ enqueue 順の話）。これにより同深さノードの並びが決定的になる。
- **ツリーはキュー長で制限**。子を積むときキュー満杯なら、その子は enqueue されず**その枝は枯れる**（実行されない）＋`queue_overflow` フラグ（§10）。落とさず benign・フラグで記録、の流儀。
- 退避スタックを使わない（self-postは即return）ので、**深い／広いツリーでもVMスタックは増えない**。コストはキュー占有に一元化される。

例と期待出力（回帰基準）は §14「検証サンプル: self-post の世代展開（BFS）」を参照。

## 7. 制御フロー（確定）

### 条件分岐 `(式) -> IFYES`

条件分岐も「ポートに送る」に畳む。式が生んだ真偽値を制御ポート `IFYES` に送ると続くブロックを実行する。

```
(TEMP > HOT) -> IFYES
    "TOO HOT!" -> STDOUT
    "I NEED AN ICE CREAM!" -> STDOUT
ELSE
    "FINE" -> STDOUT
END
```

- `ELSE` 節あり（確定・省略可）。
- 全ブロックが明示 `END` で閉じるため **dangling-else は原理的に発生しない**。
- **ネスト上限あり**: 運用1〜2段。実装は**4段ぶん静的確保**。超過はコンパイルエラー。

バイトコード（実装ガイド、新opcode不要・`JZ`/`JMP`のみ）:

```
ELSEなし:                 ELSEあり:
   <条件評価>                <条件評価>
   JZ  L_END                 JZ  L_ELSE
   <本体>                    <THEN本体>
L_END:                       JMP L_END
                          L_ELSE:
                             <ELSE本体>
                          L_END:
```

### `WAIT` = yield-until（確定・INIT/MAIN）

- `<ms> -> WAIT` は「指定時間だけ自分を中断して制御を返す」。busy-waitしない。
- **MAIN** が待っている間は `ON …` が普通に発火する（機器は固まらない）。**INIT** が待っている間は世界が凍結しており `ON …` は発火しない（§1）。yield先での違いはこの1点のみ。
- **コンテキスト切替が起きるのは「文の境界」と「WAIT」だけ**。文の途中にハンドラが割り込まない → 共有状態の競合を考えなくてよい。
- **`WAIT` を実行できるのは `INIT`・`MAIN`（yield可能ブロック）**。`ON XXX` 内に `WAIT` が現れたら**コンパイルエラー**（ランタイム無視ではなく書いた瞬間に弾く）。チェックは「今コンパイル中が yield可能ブロック（INIT/MAIN）か」のフラグ1個。
  - `ON` で禁止する理由: ハンドラでyieldを許すと「実行途中で待つフレーム」が生じ、ローカル退避・多重起動の判断が芋づる式に増える。極小VM・省メモリ方針と衝突する。
  - `INIT` で許せる理由: 起動時1回きり・走行中は他が動かない・MAINと時間的に重ならない。ゆえに中断スロットを MAIN と共用でき、上記コスト源がそもそも生じない。
- ハンドラで「一定時間後に何かしたい」は `WAIT` ではなく `TIMER`（§8）で書く。

### `EXIT` = 早期リターン（確定・`値 -> EXIT` 拡張＋単独 `EXIT` 略記, v0.4.5）

`値 -> EXIT` は、実行中のブロックを**その値を返して即座に打ち切る**リターン文。v0.4.5 で裸の `EXIT`（v0.4.2）を **`値 -> EXIT`（値付き）へ拡張**し、**単独 `EXIT` は略記として存続**させた（後方互換）。意味は文脈で決まる:

- **スクリプト内ポート `PORT … END`（§3）**: 値を**戻り値**として呼び出し元へ返す（`RESULT`/`SRESULT` へ置く）。値の型は `def_port` 宣言（`T_INT`/`T_STR`）と**整合必須**（不一致は `ERR_TYPE_MISMATCH`）。
- **ハンドラ `ON … END`**: 値は**捨てられ**、ハンドラを早期リターンするだけ。
- **単独 `EXIT`**: 「**戻り型のデフォルト値を返す**」略記。ハンドラ/`T_INT` ポートは `0 -> EXIT`、`T_STR` ポートは `"" -> EXIT` と同義。**`END` 到達時のフォールスルーと完全に同一**（「特に返すものなく、ここで抜ける」）。既存スクリプトの裸 `EXIT` はこの形でそのまま通る（破壊的変更なし）。
- **`EXIT` されず `END` へ達したら**: スクリプト内ポートは **`0`（int）/空文字（str）を産出**。ハンドラは単に完了。

```
PORT ABSDIFF                       // |ARG[0]-ARG[1]| を返す（T_INT）
    (ARG[0] >= ARG[1]) -> IFYES
        ARG[0] - ARG[1] -> EXIT    // 戻り値（int）
    END
    ARG[1] - ARG[0] -> EXIT
END

ON RXDATA
    (SARG[2] == "") -> IFYES
        "empty payload, skip" -> STDOUT
        0 -> EXIT                  // ハンドラ早期リターン（値は捨てられる）
    END
    SARG[2] -> COUNTER
    "len=", RESULT -> STDOUT
END
```

- **ブロック全体を抜ける**（C の `return` 相当）。ネストした `IFYES` の**内側から書いても**、その IFYES だけでなく**ブロックごと**抜ける（`break` のような一段脱出ではない）。「エラーを見つけたら深いネストから一気に脱出」が素直に書ける。
- **`INIT`/`MAIN` では構文エラー**（`ERR_SYNTAX`）。`EXIT` の意味を「ハンドラ／スクリプト内ポートから返る」に固定するための制限。判別は `WAIT` の「ON不可」判定のちょうど逆で、yield可能ブロック（INIT/MAIN）フラグ1個を見るだけ。
- 実装: 値を評価して型チェック後、`RESULT`（int・新 `OP_STORE_RESULT`）／`SRESULT`（str・既存 `OP_STORE_SSTR`）へ置き、`OP_HALT` を吐く。`HALT` は**呼び出しスタックが非空ならポートからの return（`ARG`/`SARG` 復帰＋戻り番地へ）**、空なら従来どおりブロック完了（`EXEC_DONE`）。ハンドラ/スクリプト内ポートは yield しないので途中 HALT は安全に効く（オペランドスタックは文境界で空）。

### `REPEAT` = 有界ループ（確定・within-tick, v0.4.4）

`<N> -> REPEAT … END` で本体を N 回実行する。本体内で反復カウンタ `ITR` が **1..N** を返す。

```
0 -> GVAR[0]                 // 合計
10 -> REPEAT
    ITR, ITR * ITR -> VAR    // VAR[ITR-1] = ITR^2 を埋める（動的ライト, §4）
    GVAR[0] + ITR -> GVAR[0] // 1..10 を合計 = 55
END
10 -> REPEAT
    ITR -> VAR -> STDOUT     // VAR[0..9] を走査して出力（動的リード）
END
```

- **`ITR`** は `REPEAT … END` 内だけで有効な読み取り専用の値源。現在の反復回数 **1..N（1始まり）**。ネスト時は**最内**ループを指す。
- **N は入口でスナップショット**（ループ中に元を変えても効かない）。`N ≤ 0` は0回（本体スキップ）。
- **ネストは `CFG_LOOP_NEST=4` 段まで**（超過はコンパイルエラー）。ループ状態（カウンタ/上限/`ITR`）は vm のループフレームに持つ（オペランドスタックではない）。
- **`REPEAT` 内で `WAIT` はコンパイルエラー（`ERR_WAIT_IN_LOOP`）**。これにより **`REPEAT` は「1 tick 内で完結し、決してティックをまたがない within-tick 構造」**になる（yield またぎのループ状態永続化・resume 時 sp リセット問題を根絶）。検出は `repeat_depth>0` フラグ1個。**`TIMER` は許可**（yield せず「予約して継続」＝within-tick を壊さない）。
- **暴走ガード**: 後退辺も1命令ずつ `CFG_INSTR_BUDGET` を消費。超過時は **`END` の直後へ pc を飛ばして打ち切り**＋`STATUS` に `ERR_BUDGET`（中断点が常に文境界＝MAIN の resume も破綻しない）。挙動要約＝「**完走 or その場で打ち切り、いずれも同一tick内で決着**」（「必ず完走」ではない）。
- **役割の線引き**: `REPEAT` は**同期・within-tick の計算用**（時間は進まない）。**時間を進めるペース配分は MAIN＋WAIT／`ON <周期>`／self-post 反復**で書く。深い/重い反復でタイミングを乱したくないなら self-post（1歩/tick・tick を専有しない）。深い `REPEAT` はその tick を最大バジェット分伸ばす＝ジッタに注意（クラッシュはしない）。

## 8. タイマ `TIMER`（確定）

`<ms> -> TIMER` は「Nミリ秒後に自分自身へ1発 `post` を予約する」出力ポート。発火は既存のイベントキュー＆ディスパッチをそのまま使うので、`ON TIMER` は `ON UART1` と同じ扱い。**新しい実行モデルは増えない**。`WAIT` と違い「予約して即return、後で別イベントとして上がる」ため、ハンドラ内から張ってもフレーム退避問題が起きず、`WAIT` 禁止と共存する。

```
ON BTN
    1 -> BUZZER
    300 -> TIMER        // 300ms後に ON TIMER を1回
END

ON TIMER
    0 -> BUZZER
END
```

確定した割り切り:

- **ワンショット1種のみ**。周期化は `ON TIMER` 内で `500 -> TIMER` と**自己再アーム**して作る（定間隔は `ON <周期>` でも書ける）。
- **固定スロット**（例: 4本）。満杯で `… -> TIMER` したら**無視＋オーバーフローフラグ**（キュー満杯と同じ思想）。
- **`ON TIMER` への `ARG` は無し**。
- 同じ `TIMER` を複数回張ったら**それぞれ独立した1発**（同名でも合体させない）。張った回数だけ上がる。
- **INIT 内で張った `TIMER` の締切は t0 起点**（§1）。張った時点では t0 未確定（以後さらに `WAIT` し得る）なので期間だけ保持し、**INIT脱出時に `締切 = t0 + 期間` へ解決**する。よって INIT中に満期することはなく、必ず RUN に入ってから発火する（INIT中は発火ゼロ、§10 と整合）。

実装: `script_tick()` が毎回 `NOW` を見て満期スロットを `post` するだけ。必要なのは「発火時刻＋対象」を持つ小さな固定配列1本。

周期化の例:

```
ON TIMER
    TOGGLE -> LED1
    500 -> TIMER        // 自分でまた張る = 周期化
END
```

## 9. 式と型（確定）

- **値の型は int と str の2択**（v0.4.2で内部 CHAR タグを撤去し純化）。数値型は **int32** 基準。小数は当面なし（必要なら固定小数点を後付け、§16）。
- 「文字」は独立した型を持たない: 文字リテラル `'A'` は int 65 の別表記（§2）、UART受信1バイトも int、数を文字グリフとして描くのは出力側の変換（`CHR`/`FORMATTER %c`・§3）の仕事。**値は数か文字列、レンダリングは出力の責務**、という分離。
- 真偽は int で代用（0/非0）。文字列は式に直接は乗らない（文字列分岐は `EQUALS` Utility経由、§3）。
- 式に使えるもの: 数値リテラル（10進/16進/2進）、入力ポート読み（`I2C1`,`NOW`,`STATUS`）、`def_const`、`GVAR[k]`/`VAR[k]`/`ARG[k]`、`RESULT`、`( )`。
- 演算子（優先順位は概ね高い順）:
  - 単項: `NOT`（論理否定） / `~`（ビット反転） / 単項 `-`
  - 算術: `*` `/` `%` → `+` `-`
  - シフト: `<<` `>>`
  - 比較: `> < >= <= == !=`
  - ビット: `&` → `^` → `|`
  - 論理: `AND` → `OR`（短絡評価）
- **ブール論理**（`AND/OR/NOT`、結果0/1・短絡）と**ビット演算**（`& | ^ ~ << >>`、32bit全体に作用）は別物として両方持つ。
- 引数位置（`X, Y, Z -> target` の各要素）にも任意の式を書ける（`(A<<2)|B, C*D -> target`）。`+` 等が `,` より強く結合。

### ゼロ除算（確定）

- `x / 0` と `x % 0` は**結果0で継続**（停止しない）。
- 同時に `STATUS` の `ERR_DIVZERO` ビットを立てる（§12）。`RESULT` には 0 が入る。
- NaN／無効値の伝播は導入しない（「0除算が起きた事実」はフラグで持つだけ、という割り切り）。

## 10. 割り込み・イベントの仕組み（確定）

非同期源（割り込み/DMA完了/他タスク通知/UART受信…）はすべて**1本の橋に集約**。C側の `post_msg` は実質 **`値 -> ポート` のC版**。

```c
/* 実ISRは最小限。積んで即return。コンテキスト/再入は気にしない */
void irq_uart1_rx_isr(UART1 *uart){
    script_post_msg("UART1", uart->ch);  /* 受信バイトを int で1件積む（v0.4.2: char型撤去） */
}
```

```
ON UART1
    ARG[0] -> CHR -> STDOUT   // 受信バイト(int)を文字に変換してエコー（v0.4.2・§3）
END
```

> v0.4.2 で CHAR タグを撤去（§9）したため、受信バイトは `ARG[0]` に **int** で入る。グリフとして出すには `CHR`（int→1文字str）を挟む。旧 `ARG[0] -> STDOUT` は 10進数を出すので注意。

ルールと割り切り（合意済み）:

- **ISR安全にする必要があるのは `post_*` の「キューに積む」操作だけ**（短いクリティカルセクション／SPSCリングバッファ）。それ以外は気にしない。
- `script_tick()` がキューを drain して該当 `ON` へディスパッチ。キュー＆ディスパッチは**1系統**。`TIMER` 満期もこの経路に乗る。
- `ARG[]` は int、`SARG[]` は str の位置ビュー（§4）。受信バイトは int で `ARG[0]` に入る（v0.4.2・CHAR撤去）。文字グリフで出すなら `CHR`（§3）。
- **キューは固定長**。溢れたら**新着ドロップ＋オーバーフローフラグ**（フラグは観測可能に）。
- **高頻度源**（例: 115200bpsのUART rxを1バイト1イベント）は、Cグルーで**行/チャンク単位にまとめてpost**しイベント数を激減させる。
- **INITフェーズ中は橋を閉じる**（§1）。INIT完走までは `post_msg*` を**no-opで破棄**する（キューに積まない・オーバーフローフラグも立てない＝「溢れ」ではなく「まだ稼働していない」ため）。割り込み起源を含む全イベントが入口で消えるので、t0 時点でキューは構造上必ず空。境界レース対策として INIT→RUN 切替の瞬間にキューを空リセットする。これにより「INIT中のイベントは捨てる」を**保証**する。

### 生ISRからの直接post（MPSC安全・v0.4.1 確定）

`script_post_msg*` は**任意の割り込みハンドラの中から直接呼んでよい**（`HAL_GPIO_EXTI_Callback` 等の生ISRで `script_post_msg("BTN", …)` を直に叩ける）。従来「postはISR安全」と述べていたが、キュー実体（SPSCリング）は**単一生産者前提**だった点を、v0.4.1で**MPSC（複数生産者・単一消費者）安全**に格上げして正式保証する。

- **なぜ必要か**: 生産者はISRだけではない。スクリプト自身が `値 -> ハンドラ源`（self-post）や `INVOKER` で**メイン文脈から**enqueueするし、複数のISR（ボタンEXTI／UART RX 等）も enqueue する。生産者が複数になると `evq_tail` 公開の read-modify-write が競合し得る（低頻度ゆえ実害は稀だが潜在レース）。
- **対策**: enqueue（`evq_push` の tail 公開まわり）を**短いクリティカルセクションで囲う**だけ。消費（`script_tick` の dequeue）はメインループ1本のままで、生産側だけを保護すればMPSC安全になる（single-consumer は不変）。
- **プラットフォーム非依存**: 割り込み禁止/復帰の作法はターゲット依存なので、コアは `YJ_ENTER_CRITICAL()` / `YJ_EXIT_CRITICAL()` の**2マクロ越し**に囲む。**コアは既定で空定義**（純C・ホスト非依存を維持）で、各ホストが自ターゲットへ割り当てる（STM32=CMSIS `PRIMASK` 退避）。詳細は §11。生産者が実質1つしか無いホスト（PCモック等）は空マクロのままでコスト厳密ゼロ。
- 帰結: ホストサンプルの「ISRではフラグだけ立て、実postはメインループ側で」という回避策は不要になる。生ISRは従来どおり「積んで即return」でよく、再入・多重ISRも安全。

### `script_tick` の処理単位＝1世代（確定）

`script_tick` が1回で処理するキュー量を**「tick開始時点のスナップショット（＝その瞬間にキューにある全件）」**と定める。1件だけでも、空になるまで全部でもない、**世代（generation）単位**。

- **規則**: tick開始時にキューにある要素をそのtickで全件ディスパッチする。**drain中に積まれた子（次世代）は今回のtickには含めず、次tickへ繰り越す**。
- **帰結（BFS）**: FIFOキューの「tick開始時の集合」はBFSの1フロンティア（同一深さの全ノード）に等しいので、self-post で生成するツリーは**幅優先で展開し、世代境界がtick境界になる**（§6「self-post の世代展開」）。
- **enqueue順は出現順**: 1つの `ON` 本体内の複数 post は、本体を上から実行して当たるたびに即 enqueue するため、**ソース上の出現順**でキュー末尾に並ぶ。これが同深さノードの並び（兄弟順）を決定的にする。
- **満期・割り込み・self-post は同一規則**: 周期満期／`TIMER`満期／割り込み起源post／self-post は、すべて同じキューに乗り同じ世代drainで処理される。`ON <周期>` が同tickに複数満期したときの「定義順で全件実行」（§6）も、この世代drainの一帰結（満期分はtick開始時スナップショットに含まれる）。catch-up/coalesce（§6）は満期"回数"の話で、世代drainの"順序・粒度"とは直交し両立する。
- **ツリーはキュー長で制限**: 子のenqueueがキュー満杯に当たると、その子は積まれず**枝が枯れる**（実行されない）＋`queue_overflow` フラグ。落とさず benign・フラグで記録、の流儀。命令数バジェット（§1）も併存し、1ノードがバジェットを使い切れば中断・次tick再開する。

> 実装メモ（**区切り方は実装依存**・挙動は上記で確定）: 「tick開始時スナップショット」を実現する区切り方には少なくとも2方式があり、**どちらでも挙動は同一**なので実装側の自由とする。
> - **(i) 長さスナップショット方式**: tick開始時にキュー長 `n` を読み、その回数だけループして処理する。drain中に末尾へ積まれた子はループ回数に入らず次tickへ。
> - **(ii) 番兵マーカー方式**: tick開始時に番兵（マーカー）を末尾に積み、それに当たるまで処理する。マーカー以降に積まれた子は次tickへ。
> いずれも固定長キュー・追加メモリ僅少。リングバッファのインデックス境界の取り回しで好みの方を採る。

### 受信引数の充填（`ARG` / `SARG`・確定）

`post` 時のタグ付き argv が、dispatch時に位置どおり `ARG[k]`/`SARG[k]` へ充填される（読み出しビューは§4）。

- **int/char タグ**は4バイトでそのままキューに乗る（従来どおり）。
- **str タグ**は遅延ディスパッチ対策として、**post の瞬間に文字列バイトをキューエントリ内の `SARG` バッファへコピー**する（ハンドラが走る頃に元バッファが再利用され得るため）。コピー時に `SARG` バッファ長を超えたら**切り詰め＋`ERR_STR_TRUNC`**（§12の既存フラグを再利用、新フラグ無し）。
- 混在・複数引数は**1イベントとしてアトミックに**積むマルチ引数post `script_post_msg_v`（§11）で渡す。1回のクリティカルセクションで enqueue。
- パケット系の源は生ISRで1バイトずつではなく「1パケット組み上げてから」postするのが定石（§16「高頻度源はチャンク単位でpost」）。既存の単値post 2本（`script_post_msg`/`_char`）はそのまま残す。

例（RX = 送信元addr, 宛先addr, データ文字列）:

```c
/* グルー側（1パケット組んで1回post） */
script_arg_t a[3] = {
    SCRIPT_ARG_INT(src),
    SCRIPT_ARG_INT(dst),
    SCRIPT_ARG_STR(payload, len),
};
script_post_msg_v("RX", 3, a);
```

```
ON RX
    "from ", ARG[0], " to ", ARG[1] -> STDOUT
    SARG[2] -> SGVAR[0]      // データ文字列を保持
    SARG[2] -> COUNTER
    "len=", RESULT -> STDOUT
END
```

### `値リスト -> ハンドラ源`（self-post・確定）

ハンドラ源（`def_handler` で宣言した源、または起動時に自動registerされる既定の `HANDLER`）は、スクリプトの `->` **右辺に立てられる**。`値リスト -> 源` と書くと、`script_post_msg_v` と**同じ経路で即時1発post**する（`値 -> ハンドラ源` は正式許可・旧 `ERR_SYNTAX` 廃止）。`HANDLER` は特殊機構を持たず、ユーザー定義のハンドラ源と内部完全同格。

- **非再帰**: その行で `ON 源` 本体へ降りない（即キュー投入して即return）。実行は次tick以降のディスパッチ。`値 -> 源` は関数呼び出しではなく `TIMER` 張りと同類、と読むこと。
- **充填は `ON RX` と完全同型**: 左→右の値が位置どおり `ARG[k]`/`SARG[k]` に**位置共有ビュー**で入る（§4）。int/str 混在可・多値可。型不一致/不足は benign（`0`/空文字）。
- **ハンドラ源は産出none＝チェイン終端のみ**（§3）。`… -> FORMATTER -> MYHANDLER`（加工結果をイベントとして投げる）は終端として可。中間には立てない（`ERR_BAD_POSITION`）。チェイン終端→次世代のハンドラ起動、で self-post の世代展開（§6）と繋がる。
- INITフェーズ中は橋が閉じているので self-post も no-op 破棄（§1）。INIT→RUN 切替時のキュー空リセットでクリア。※**`AFTER` を付けた遅延post は例外**で、INIT中でも破棄せず t0 起点で解決する（下記）。
- ユーザーは `def_handler(NAME)`（C側 `script_register_handler`）で同種の self-post 源を任意個作れる。`HANDLER` はCグルー無しの最小構成でも self-post が即動くよう、起動時に1本だけ既定で在る（電池付属）。

### 遅延post `値リスト -> ハンドラ AFTER <ms>`（確定・v0.4.7）

**引数を持ったまま、任意のハンドラを N ms 後に起動する。** `->` の意味（値がハンドラへ流れる）はそのままで、`AFTER` はその配送を**いつ届けるか**を修飾するだけ。

```
CODE, POSITION -> MORSE_SYMBOL_END AFTER TONE_TIME   // TONE_TIME(ms) 後に ON MORSE_SYMBOL_END
none -> KICKOFF AFTER 3000                            // 引数なしでも可
```

- **`AFTER` の式は int（ms）**。変数・式でよい（`AFTER TONE_TIME`・`AFTER UNIT_MS * 3`）。**`<= 0` は即post に縮退**（エラーにしない）。
- **ハンドラ源宛のみ**。`out`/`inout`/スロット等に付けたら `ERR_BAD_POSITION`。
- **満期後は普通の post と完全に同一経路**：pending 表から通常のイベントキューへ enqueue → 次tickのディスパッチで `ON <名前>` が走る。充填規則（`ARG`/`SARG` 位置共有・benign）も self-post と同型。
- **文字列引数は post 時にコピー**（pending が payload の実体を持つ）。満期までに元の `SVAR` が書き換わっても、届く値は post した瞬間のもの。
- **INIT では `TIMER` の作法**（v0.3.4 `init_armed` と同じ）: INIT中の遅延postは破棄されず、**t0 起点**で解決する。橋を閉じる目的は「**外来**イベントの t0 スタンピード防止」であり、遅延postは**スクリプト自身が書いた予約**なので対象外、という理屈。→ **`INIT` からスクリプト定義ハンドラの起動を予約できる**（v0.4.6 までは書けなかった）。
- **キャンセルは無い**（`TIMER` と同様）。同tickに複数満期したときの相互順序は未規定（§16）。
- **資源と失敗**: pending 表は `CFG_DELAY_SLOTS`（既定4）。**post時に満杯なら新着を捨てて `ERR_DELAY_FULL`(0x20)**、**満期時にキューが満杯なら既存 `ERR_QUEUE_OVF`**（2箇所を切り分けられる）。
- **`TIMER` との関係**: 遅延post は概念上 `TIMER` を**包含**する（`TIMER` ＝「引数なし・宛先が `ON TIMER` 固定」の遅延post）。`TIMER` は既存互換のため据え置くが、新規コードは `AFTER` の方が素直に書けることが多い。
- **典型（spin の追放）**: `NOW` を毎tickポーリングして自分を post し直す「遅延の自前実装」は不要になる。状態も `START_TIME` を持ち回らずに済むので `ARG` が空く:
  ```
  ON MORSE_SYMBOL                    // (code, position)
      1 -> LED1
      CODE, POSITION -> MORSE_SYMBOL_END AFTER TONE_TIME
  END
  ON MORSE_SYMBOL_END                // (code, position)
      0 -> LED1
      CODE, POSITION + 1 -> MORSE_SYMBOL AFTER GAP_TIME
  END
  ```

```c
/* 初期化: ヒープ不使用、固定アリーナを渡す */
void  script_init(void *arena, size_t arena_size);

/* コンパイル時バインド（INIT前に呼ぶ）。向き＝関数名／産出型＝引数 */
/* 産出型 enum（out 以外で必須）。out は産出none確定なので受け取らない */
typedef enum { SCRIPT_T_INT = 0, SCRIPT_T_STR } script_type_t;

void  script_register_const (const char *name, int32_t value);
/* out: 右辺のみ・産出none・終端。戻り値を持たない */
void  script_register_out   (const char *name, void (*fn)(int argc, const int32_t *argv));
/* in: 左辺のみ・産出型必須。int産出は戻り値、str産出はfn内で script_set_sresult（戻り値は無視） */
void  script_register_in    (const char *name, int32_t (*fn)(void), script_type_t out_type);
/* inout: 両辺OK（中間可）・産出型必須。副作用＋ int産出=script_set_result / str産出=script_set_sresult */
void  script_register_inout (const char *name, void (*fn)(int argc, const int32_t *argv), script_type_t out_type);
void  script_register_handler(const char *name);  /* ON <name> 用ハンドラ源（値->name で self-post 可） */

/* 関数ポートthunkから戻り値をRESULTへ入れる */
void  script_set_result(int32_t v);

/* 非同期源 → VMへの橋（ISRから呼べる。積んで即return） */
int   script_post_msg       (const char *name, int32_t value);  /* int値（単値） */
/* v0.4.2: CHAR型撤去により post_msg_char は post_msg と同義。互換のため薄い別名で残す
   （新規コードは post_msg でよい）。受信バイトはそのまま int として ARG[0] に入る。 */
int   script_post_msg_char  (const char *name, char    ch);     /* = post_msg（互換別名） */
/* 混在・複数引数を1イベントとしてアトミックに積む（RX等のパケット系）。
   script_arg_t = { tag(INT/STR), int値 or (const char *ptr, len) }。  ※CHARタグは撤去(v0.4.2)
   組み立てマクロ: SCRIPT_ARG_INT(v) / SCRIPT_ARG_STR(ptr,len)。SCRIPT_ARG_CHAR は SCRIPT_ARG_INT の別名で温存。
   str引数はpost時にSARGバッファへコピー（超過は切り詰め＋ERR_STR_TRUNC）。 */
int   script_post_msg_v     (const char *name, int argc, const script_arg_t *argv);
/* 戻り値: 0=ok / <0=キュー満杯（オーバーフローフラグも立つ） */

/* スクリプト全文を受け取りコンパイル＆差し替え。RAM常駐・揮発 */
int   script_load(const char *src, size_t len);    /* 0=ok / 非0=ロードエラー(script_err_t) */
const script_error_t *script_last_error(void);     /* 直近ロード失敗の構造化詳細 */
const char *script_strerror(script_err_t code);    /* 任意リンク・デバッグ補助。コア必須ではない */

/* 1ステップ進める（メインループから周期呼び出し）。タイマ満期もここで処理 */
void  script_tick(void);
```

### enqueue 保護マクロ（ISR直post・MPSC安全・v0.4.1）

生ISRからの直接post（§10）を安全にするため、コアは enqueue（`evq_push` の tail 公開）を次の2マクロで囲む。**割り込み禁止/復帰はターゲット依存**なので、コアは既定で空に定義し、各ホストが必要なら自ターゲット向けに再定義する（ホスト非依存を保つ）。

```c
/* コア既定（例: script_config.h）。単一生産者しか無いホストはこのままでコスト0 */
#ifndef YJ_ENTER_CRITICAL
#define YJ_ENTER_CRITICAL()   ((void)0)
#endif
#ifndef YJ_EXIT_CRITICAL
#define YJ_EXIT_CRITICAL()    ((void)0)
#endif

/* STM32 ホスト側での割り当て例（CMSIS・PRIMASK退避で再入安全） */
/* #define YJ_ENTER_CRITICAL()  uint32_t _pm = __get_PRIMASK(); __disable_irq() */
/* #define YJ_EXIT_CRITICAL()   __set_PRIMASK(_pm) */
```

- 保護するのは**生産側（enqueue）だけ**。消費（`script_tick` の dequeue）はメインループ単独なので保護不要（single-consumer）。
- クリティカルセクションは tail 更新の数命令のみ＝割り込み禁止区間は極小。PCモック等 単一生産者のホストは空マクロのままでよい。

### ロードエラー（構造化・確定 / (B)方針）

`script_load` の失敗理由は**構造化データ**で返す。文字列化・表示・言語・did-you-mean は**コアでは行わず、組み込む人の領域**（コアは「失敗の事実＋判断材料」だけ返す）。

```c
typedef enum {
    ERR_NONE = 0,
    ERR_END_EXPECTED,    /* ブロックが END で閉じてない。aux=開きヘッダの行 */
    ERR_UNEXPECTED_END,  /* 対応ヘッダの無い END */
    ERR_UNKNOWN_PORT,    /* 未登録の送り先。tok=その名前 */
    ERR_UNKNOWN_NAME,    /* 未登録の入力ポート/const/源。tok=その名前 */
    ERR_TYPE_MISMATCH,   /* int/str スロットの型違い代入（§4） */
    ERR_WAIT_IN_ON,      /* ON ハンドラ内の WAIT（§7） */
    ERR_BAD_SLOT_INDEX,  /* 添字が定数でない/範囲外（§4, §12） */
    ERR_NEST_TOO_DEEP,   /* ネスト上限超過（§12） */
    ERR_BAD_POSITION,    /* ポート向き違反: in を右辺/out を左辺/産出noneを中間（§3） */
    ERR_TOO_MANY_PORTS,  /* スクリプト def_handler/def_port でポート表が満杯（§3, v0.4.1/v0.4.5） */
    ERR_WAIT_IN_LOOP,    /* REPEAT ループ内の WAIT（§7, v0.4.4） */
    ERR_RECURSION,       /* スクリプト内ポートの再帰サイクル。tok=サイクル上のポート名（§3, v0.4.5・load時DFS） */
    ERR_SYNTAX           /* 上記に当てはまらない構文崩れ（受け皿） */
} script_err_t;

typedef struct {
    int16_t      line;   /* 1始まり。0=行特定不可（全体） */
    script_err_t code;
    int16_t      aux;    /* 補助。ERR_END_EXPECTED の開きヘッダ行 等。無ければ0 */
    char         tok[];  /* 問題トークン断片（"HOSTCMP" 等）。長さは §12 の識別子最大長 */
} script_error_t;
```

- **最初の1エラーで停止**（ワンパス・エラー回復を持たない＝最軽量）。直して即再ロードの運用に合う。
- 表示例（埋める人が組む）: `line 20: unknown port 'HOSTCMP' — did you mean 'HOSTCMD'?`（did-you-mean は手元の登録名と `tok` の編集距離照合で実装可・コア非搭載）。
- **ロード時エラー（`script_err_t`）と実行時異常（`STATUS`ビット, §12）は完全に別系統**。前者は入口の門前払い（一度きり・`script_load` 戻り値）、後者は走行中の観測可能フラグ。名前空間が `ERR_` で被るが別物。

## 12. メモリ・安全性（確定方針）

- 全RAMは初期アリーナ内で完結（ヒープ無し）。スクリプトのRAM使用量は**コンパイル時に静的見積もり可能**。
- 安全機構: 添字境界チェック（**定数添字はコンパイル時完結／動的添字 `N -> SLOT` は実行時に範囲外→0縮退＝メモリ安全**, §4）、命令数バジェット（暴走防止・`REPEAT` 超過は打ち切り＋`ERR_BUDGET`）、ネスト深さ上限（`IFYES`／`REPEAT` とも4段）、**スクリプト内ポートの再帰/深度は load 時の静的DAG判定で一律に弾く（サイクル=`ERR_RECURSION`〈tok=ポート名〉・最長路が `CFG_CALL_NEST` 超過=`ERR_NEST_TOO_DEEP`・実行時溢れは静的に到達不能, v0.4.5）**、ゼロ除算トラップ、`WAIT`位置チェック（`ON` 内・`PORT` 内・`REPEAT` 内は不可）。
- 異常時は**エラーで停止しホストメモリは破壊しない**。**ロード時エラー**（構文/未登録名/型違い/WAIT位置/ネスト等）は §11 の `script_err_t` で `script_load` が返す。**実行時異常**（0除算/キュー溢れ/タイマ満杯/文字列切詰）は `STATUS` ビット。両者は別系統。

### リソース設定ガイド（別ドキュメントへ分離）

`script_config.h` の各 `#define` と RAM の効き方（どれを増やすとアリーナが増えるか・RAM 消費を支配する乗数・減らすと何ができなくなるか）は、独立したポーティングガイド **[docs/resource_config.md](docs/resource_config.md)** にまとめた（実測ベース）。要点だけ再掲:

- **RAM は2箇所だけ**: (a) アリーナ＝`sizeof(script_vm_t)` の一塊（固定スロット・ポート表・イベントキュー・コールスタック・バイトコード・文字列プールが同居）、(b) コンパイラ内の少量 static（別名表・DFS作業・アリーナ外の `.bss`）。**どの `#define` もコードサイズはほぼ変えない**。
- **既定 ≈ 13.0KB**（v0.4.7 の pending 表 `CFG_DELAY_SLOTS=4` で +約720B）。大物は ポート表(`CFG_MAX_PORTS`)・イベントキュー(`CFG_EVENT_QUEUE_LEN`)・コールスタック(`CFG_CALL_NEST`)・`CFG_CODE_SIZE`・`CFG_STRPOOL_SIZE`・**遅延post の pending 表(`CFG_DELAY_SLOTS` × ≈180B)**。
- **RAM 消費の支配項は文字列の「長さ×本数」**: `CFG_SSTR_LEN`/`CFG_SARG_LEN` は基本スロット＋コールスタック＋イベントキュー**＋遅延post の pending 表（v0.4.7）**の複数箇所に同時に効く（＝レバレッジ大）。`SARG_COUNT` の +1枠 ＝ `SARG_LEN × (1 + CALL_NEST + QUEUE_LEN + DELAY_SLOTS)`。
- **キューエントリは一律固定サイズ**（文字列を持たないイベントも `event_t` 満額を占める）。可変プール方式は将来ノブ（§16）。
- 実使用量は `CODE_USED` / `STR_USED`（入力ポート）で実測できる。詳細と早見表は上記ガイドへ。

### 異常フラグ（STATUS）の集約（確定）

異常はバラバラのフラグ機構を作らず、**すべて `STATUS`（ビットフラグ集合）の各ビットに畳む**。ポート一元化の精神に揃える。スクリプトからもホスト（C）からも同じフラグを読める。

- ビット例: `ERR_QUEUE_OVF`(0x01・イベントキュー溢れ)/ `ERR_TIMER_FULL`(0x02・タイマスロット満杯)/ `ERR_DIVZERO`(0x04)/ `ERR_STR_TRUNC`(0x08)/ **`ERR_BUDGET`(0x10・`REPEAT` が命令数バジェットで打ち切られた, v0.4.4)** / **`ERR_DELAY_FULL`(0x20・遅延post の pending 表が満杯で新着を捨てた, v0.4.7)**。（v0.4.5のスクリプト内ポート再帰/深度は**ロード時に静的DAG判定**で弾くため、STATUS実行時ビットは追加しない。）
- **資源ごとに専用ビット**を割り当てるのが作法（枯れた資源と対処＝どの `CFG_*` を上げるか、が1対1で分かる）。遅延postは失敗点が2つあるが、**post時の pending 満杯＝`ERR_DELAY_FULL` / 満期時のキュー満杯＝`ERR_QUEUE_OVF`** と切り分けられる（§10）。
- 読み: スクリプトは `STATUS` 入力ポート＋ビットマスク（`(STATUS & ERR_DIVZERO) -> IFYES`）。ホストは `script_get_status()` 相当。
- クリア: **明示クリア**（`ERR_DIVZERO -> CLEAR_ERR`）。立てっぱなしにせず、確認した側が落とす。
- 異常が起きても**ハンドラは継続**（落とさない・気づける）が基本方針。`ERR_xxx` 定数は組み込み（`def_const` 相当で最初から利用可）。

## 13. 文法スケッチ（簡易EBNF・実装の出発点）

```
program     = decl_blk? { def | block } ;      // 宣言は冒頭一括（block より前）
decl_blk    = { alias_decl | handler_decl | port_decl } ;
alias_decl  = "def_alias" "(" NAME "," alias_body ")" NL ;
alias_body  = ("GVAR"|"SGVAR") "[" NUMBER "]"   // (A) 大域スロット（読み書き可・型継承）
            | STRING                            // (B) 文字列リテラル（読専）
            | NUMBER ;                          // (C) 整数リテラル（読専）
handler_decl= "def_handler" "(" NAME ")" NL ;   // スクリプト側ハンドラ源宣言（v0.4.1・コンパイラが解釈）
port_decl   = "def_port" "(" NAME "," ("T_INT"|"T_STR") ")" NL ; // スクリプト内ポート宣言（v0.4.5）
// def_alias は #define 相当の字句マクロ。NAME 出現は alias_body のトークン列へ展開してから
// 通常処理（バイトコードに別名は残らない）。VAR/ARG は対象外。冒頭以外の def_alias は ERR_SYNTAX。
// def_handler(NAME) はハンドラ源ポートを1本登録（冪等・C登録済みなら no-op）。以後 ON NAME /
// 値 -> NAME が解決。満杯は ERR_TOO_MANY_PORTS。冒頭以外の def_handler は ERR_SYNTAX。
// def_port(NAME,型) は inout・産出型付きポートを1本登録。本体は port_blk。宣言のみ/本体のみは load エラー。
def         = "def_" ... ;                  // その他 def_（def_in/out/inout/const）＝C側マクロの写し（非解釈）

block       = init_blk | main_blk | on_blk | port_blk | if_stmt ;
init_blk    = "INIT" NL local_blk stmt_list "END" ;
main_blk    = "MAIN" NL local_blk stmt_list "END" ;
on_blk      = "ON" trigger NL local_blk stmt_list "END" ;
port_blk    = "PORT" NAME NL local_blk stmt_list "END" ; // スクリプト内ポート本体（v0.4.5）。NAME は def_port 済み。
            // 本体で WAIT 不可(ERR_WAIT_IN_ON)＝within-tick。再帰はload時の静的DAG判定でサイクル=ERR_RECURSION。
            // ARG/SARG/VAR/SVAR は全て private ローカル（VMが自動退避/復帰・v0.4.6）、共有は GVAR/SGVAR のみ。戻り値は 値 -> EXIT。
local_blk   = { local_decl } ;              // ブロック冒頭一括のローカル別名（v0.4.6）。END まで有効。
local_decl  = "def_local" "(" NAME "," local_body ")" NL ;
local_body  = ("VAR"|"SVAR"|"ARG"|"SARG") "[" NUMBER "]" // VAR/SVAR=読み書き、ARG/SARG=読取専用
            | STRING | NUMBER ;             // 局所リテラル（読専）。GVAR/SGVAR は不可（def_alias で）。
            // 別ブロック間の同名ローカルは可。大域エイリアス名との衝突/二重宣言/文の後の宣言は ERR_SYNTAX。
trigger     = NUMBER [ "(" expr ")" ]       // 周期(ms)。( 条件 ) 付きは条件トリガ（エッジ, v0.4.7）
            | PORT ;                        // ハンドラ源(def_handler) / メッセージ源 / TIMER / HANDLER
            // ON <周期> (条件): 各満期で条件(int式)を評価し「前回偽・今回真」でだけ本体を実行。
            // 偽になったら自動リセット→再成立で再発火。prev はロード時 false ゆえ t0 直後の
            // 初回満期で条件が真なら発火する。インターバル必須（ON (条件) 単体は無い）。
            // 条件は純粋式（-> は expr の文法に無いので副作用は書けない）。str は ERR_TYPE_MISMATCH。

stmt_list   = { stmt NL } ;
stmt        = send | if_stmt | repeat_stmt | exit_stmt ;
exit_stmt   = ( expr_list "->" )? "EXIT" NL ;   // 早期リターン(v0.4.5)。単独 EXIT は「戻り型のデフォルト
            // 値を返す」略記(=0->EXIT / ""->EXIT・END到達と同一)＝後方互換。
            // PORT本体=戻り値(RESULT/SRESULT・型は def_port と整合)、ハンドラ=値を捨てて早期return。
repeat_stmt = expr "->" "REPEAT" NL stmt_list "END" ;      // 有界ループ(v0.4.4)。本体内で ITR=1..N。
            // 本体に WAIT 不可(ERR_WAIT_IN_LOOP)＝within-tick。ネスト CFG_LOOP_NEST=4。
send        = expr_list "->" target { "->" target } [ "AFTER" expr ] ;  // 値ルーティング文（複数引数可）。
            // AFTER <ms> は遅延post（v0.4.7）。終端がハンドラ源のときだけ許可（他は ERR_BAD_POSITION）。
            // 遅延msはint式。<=0 は即postに縮退。満期後は通常postと同一経路。pending満杯=ERR_DELAY_FULL。
            // INIT中に張った遅延postは破棄されず t0 起点で解決（TIMERの作法・§10）。
target      = PORT | SLOT ;  // SLOT=裸のスロット名＝動的添字アクセス（N->SLOT read / idx,val->SLOT write, §4 v0.4.4）
            // ->が2個以上＝チェイン(§5)。前段の産出値(RESULT/SRESULT)を次段の暗黙左辺へ挿し、
            // 複数文へコンパイル時展開。中間PORTはinoutのみ・終端は out/inout/handler/制御/スロット。
expr_list   = expr { "," expr } | "none" ;
if_stmt     = cond "->" "IFYES" NL
              stmt_list [ "ELSE" NL stmt_list ] "END" ;
cond        = "(" expr ")"                       // 従来形（条件式）
            | expr_list "->" PORT { "->" PORT } ; // チェイン終端=IFYES：前段産出を条件に(§5)

expr        = or_expr ;
or_expr     = and_expr { "OR"  and_expr } ;
and_expr    = cmp_expr { "AND" cmp_expr } ;
cmp_expr    = add_expr [ ("<"|">"|"<="|">="|"=="|"!=") add_expr ] ;
add_expr    = unary { ("+"|"-") unary } ;
unary       = [ "NOT" ] primary ;
primary     = NUMBER | CHARLIT | STRING | PORT | CONST | "ITR"
            | "RESULT" | "SRESULT"
            | ("GVAR"|"VAR"|"ARG")    "[" NUMBER "]"   // int型スロット
            | ("SGVAR"|"SVAR"|"SARG") "[" NUMBER "]"   // 文字列(str型)スロット
            | "(" expr ")" ;
CHARLIT     = "'" ( CHAR_ESC | /* 制御・引用符以外の1文字 */ ) "'" ;  // v0.4.2: int値(=ASCIIコード)。NUMBERと同格
CHAR_ESC    = "\\" ( "r" | "n" | "t" | "\\" | "'" ) ;
// CHARLIT は int（NUMBER と同じ int 型ソース）。'A'==0x41。文字列(str)ソースは STRING と S* スロット。
// 型分離はスロット名でコンパイル時に判定（§4）。ARG/SARGは受信専用（読みのみ・動的添字もreadのみ）。
// ITR は REPEAT…END 内だけ有効な反復カウンタ(1..N・読専, v0.4.4)。動的添字は send の target=SLOT を参照。
```

### 検証サンプル: 周期満期ポリシー（catch-up / coalesce）（正式採用）

意地悪用の予約語 `DELAY`（ハンドラ内ブロッキング。協調を無視して実時間居座る。**検証専用、実運用では使わない**）で遅延を作り、catch-up と coalesce の差を炙り出す。`GVAR[1]` が経過カウンタ。

```
INIT
    none -> SYS_INIT
END

MAIN
    1000 -> WAIT
    "MAIN1...", NOW -> STDOUT
    GVAR[1] -> STDOUT
    1000 -> WAIT
    "MAIN2...", NOW -> STDOUT
    GVAR[1] -> STDOUT
END

ON 100
    "delay1 ", NOW -> STDOUT
    (GVAR[0] == 0) -> IFYES
        550 -> DELAY              // 初回だけ550ms居座らせて満期を5回ぶんパスさせる
    END
    1 -> GVAR[0]
    GVAR[1] + 1 -> GVAR[1]
    "delay2 ", NOW -> STDOUT
END
```

期待される結果（回帰基準）:

- **catch-up（既定）**: 1秒地点 `GVAR[1]=10`、2秒地点 `=20`（パスした5回も取り戻すので 10/秒）。取り戻しは復帰直後の数tickに分散して詰めて発火（同tickバーストはしない）。
- **coalesce（オプション）**: 1秒地点 `GVAR[1]=6`、2秒地点 `=16`（パスぶんを丸めるので catch-up より4少ない）。
- 同じスクリプト・ビルド違いで `GVAR[1]` の値が変わることが、コンパイルオプションが効いている証拠。

### 検証サンプル: self-post の世代展開（BFS）（正式採用・回帰基準）

`ON RXDATA` を1回受けると `0,0 -> HANDLER` で展開を始動。各ノードはガード `GVAR[0] <= 2` の下で子2つ（`ARG[0]+1,ARG[1]` と `ARG[0],ARG[1]+1`）を**この出現順**で self-post する。`script_tick` の世代drain（§10）＋FIFOにより、展開は**幅優先・世代＝tick境界**で進む。

```
INIT
    none -> SYS_INIT
END
MAIN
END
ON RXDATA
    0 -> GVAR[0]
    0, 0 -> HANDLER
END
ON HANDLER
    ARG[0], " ", ARG[1] -> STDOUT
    (GVAR[0] <= 2) -> IFYES
        ARG[0]+1, ARG[1] -> HANDLER
        ARG[0], ARG[1]+1 -> HANDLER
        GVAR[0] + 1 -> GVAR[0]
    END
END
```

期待される結果（回帰基準）— RXDATA到達を tick1 とし、以降1tick=1世代:

```
[tick2] 0 0
[tick3] 1 0   0 1
[tick4] 2 0   1 1   1 1   0 2
```

- 出力は**7行**、順序は `0 0 / 1 0 / 0 1 / 2 0 / 1 1 / 1 1 / 0 2`。停止時 `GVAR[0]=3`、`queue_overflow=0`。
- 各世代が1tickに対応（世代境界＝tick境界）。兄弟の並びは self-post の**出現順**で決まる（例: 第2世代 `0 1` の子は `1 1`(先)・`0 2`(後)）。
- ガードは各ノード実行時の `GVAR[0]` を見る。第3世代（4ノード）は実行時 `GVAR[0]=3` で全て偽となり子を積まないため、第4世代は生まれず展開停止。
- もしキュー長が不足して子の enqueue が満杯に当たれば、その枝は**枯れ**（実行されず）`queue_overflow` が立つ（本サンプルは overflow=0 で全枝が育つ前提）。

### 検証サンプル: パイプライン・チェイン（v0.4・正式採用・回帰基準）

鎖版と複数文版が**同一バイトコード・同一出力**になることを確認する。終端=スロット／終端=IFYES／str産出跨ぎの3パターン。`VAL_CALCULATOR` は `a*b`（§14 本体サンプルと同じ推奨実装）とする。

```
INIT
    none -> SYS_INIT
END
MAIN
END

ON 1000
    // (1) 終端=スロット: 計算結果を即GVARへ（産出int → GVAR[0]）
    3, 4 -> VAL_CALCULATOR -> GVAR[0]        // = 「3,4 -> VAL_CALCULATOR / RESULT -> GVAR[0]」
    "calc->gvar = ", GVAR[0] -> STDOUT       // 12

    // (2) 終端=IFYES: 判定の連鎖（EQUALS産出int → RESULT → IFYES）
    "ON" -> SVAR[0]
    "ON", SVAR[0] -> EQUALS -> IFYES         // = 「... -> EQUALS / (RESULT) -> IFYES」
        "match" -> STDOUT
    END

    // (3) str産出を継いで終端out（FORMATTER産出str → SRESULT → STDOUT）
    "v=%x", 0xAB -> FORMATTER -> STDOUT      // = 「... -> FORMATTER / SRESULT -> STDOUT」
END
```

期待される出力（回帰基準・1秒ごとに繰り返し）:

```
calc->gvar = 12
match
v=ab
```

- 各鎖行を右コメントの複数文版に書き換えても**出力は1バイトも変わらない**（実行モデル不変の確認）。
- (3) の継ぎ目は SRESULT（str産出）を選ぶ。仮に終端を int スロット（`-> VAR[0]`）にすると load時に `ERR_TYPE_MISMATCH`。
- `3,4 -> VAL_CALCULATOR -> GVAR[0]` の中間 `VAL_CALCULATOR` は `inout`。ここを `out`（例 `STDOUT`）にすると中間に産出noneが立つので `ERR_BAD_POSITION`。

## 15. 実装の進め方（Claude Code向けフェーズ案）

1. **値・ポート・VMコア**: tagged value（int32/bool/char/strref）、ポートテーブル、固定スロット（GVAR/VAR/ARG/RESULT）、スタックVM、最小opcode（PUSH/LOAD_SLOT/STORE_SLOT/LOAD_PORT/CALL_OUT(argc)/CMP/ADD/SUB/NOT/AND/OR/JZ/JMP/YIELD/POST/HALT）。
2. **トークナイザ＋ワンパス・コンパイラ**: `式リスト -> ポート` と `INIT/MAIN/ON/IFYES…END` を直接バイトコードへ。ジャンプはバックパッチ。複数引数のargc付与、過不足の正規化。WAIT位置チェック（INIT/MAINは許可・ONは拒否）。**ポート属性チェック（向き in/out/inout で `->` の位置、産出型 int/str で格納先）＝登録表を引くだけ・実行時ゼロ**（§3）。
3. **スケジューラ**: `script_tick()`、命令数バジェット、`WAIT`のyield（INIT/MAINで中断状態を共用スロットに保存）、**2フェーズ・ライフサイクル（INIT完走→t0確定→RUN・INIT中は橋を閉じる）**、周期`ON`管理（初回はt0起点）。
4. **イベント系＋TIMER**: ISR安全リングバッファ、`post_*`／マルチ引数 `script_post_msg_v`、`ON <源>`ディスパッチ、`ARG[]`/`SARG[]`位置共有充填、全ハンドラ源のself-post（`値 -> ハンドラ源`・`HANDLER`は起動時自動registerの既定インスタンス・専用op無し）、一律固定キューエントリ、オーバーフローフラグ、タイマ固定スロットと満期post。
5. **エラー報告＋ホストAPI整備**: 構造化ロードエラー `script_error_t {line, code, aux, tok}`（文字列化せず enum で返す＝(B)方針）、最初の1エラーで停止、`script_load`差し替え、register系（**向き in/out/inout・産出型 `script_type_t`** を登録に保持／`ERR_BAD_POSITION`）、`script_set_result`／`script_set_sresult`。
6. **組み込み定番セット（v0.3）**: 演算拡張 `* / % & | ^ ~ << >>`、16進/2進リテラル、`/0 %0`→0継続＋`STATUS`ビット、`STATUS`入力ポート＋`CLEAR_ERR`、既存オーバーフロー系も`STATUS`に集約。
7. **文字列処理セット（v0.3）**: 固定長文字列スロット `SVAR/SGVAR/SRESULT`、標準Utility `SLICER/MERGER/COUNTER/FORMATTER/EQUALS`（1始まり・(開始,長さ)、切詰は`ERR_STR_TRUNC`）。
8. **パイプライン・チェイン（v0.4）**: 文パーサを `式リスト -> ポート { -> ポート }` に拡張。`->` が2個以上なら、各継ぎ目で直前段の**産出型属性**（§3）で `RESULT`/`SRESULT` を選んで次段の暗黙左辺に挿し、**複数文へ展開してから通常バイトコードを吐く**（実行モデル不変・新opcode無し）。位置チェック＝中間は `inout` のみ・`in` は右辺不可・産出none(out/handler)は中間不可（`ERR_BAD_POSITION`）、終端スロットの型違いは `ERR_TYPE_MISMATCH`（いずれも新エラーコード無し）。継ぎ目はルーズ（型チェック無し・終端スロットのみ型一致）。回帰基準は §14「検証サンプル: パイプライン・チェイン」。
9. **（任意）`REPEAT`、可変添字** を必要に応じ追加（`ON <周期>(条件)` はフェーズ13で確定採用）。
10. **スクリプト内ポート（v0.4.5）**: `def_port`/`PORT … END` パーサ、新opcode `CALL_SCRIPT`（引数を `ARG`/`SARG` へ振り分け＋caller退避＋フレームpush＋`bc_start` へジャンプ）・`STORE_RESULT`・`HALT` の文脈依存化（`call_sp>0` は return＝`ARG`/`SARG` 復帰）、`値 -> EXIT`（型チェック→`RESULT`/`SRESULT`→HALT）＋単独`EXIT`（戻り型デフォルト値=フォールスルーと同一コード）、**ロード末尾の呼び出しグラフDFS**（サイクル=`ERR_RECURSION`〈tok=ポート名〉／最長路>`CFG_CALL_NEST`=`ERR_NEST_TOO_DEEP`）、`call_sp` を各ブロック開始でリセット（`loop_sp` と同じ4箇所）、実行時深さチェックは防御assertのみ。制約(WAIT不可/VAR・SVAR共有/ARG・SARG退避)で within-tick を担保。
11. **ブロック局所別名＋ポートのprivateローカル（v0.4.6）**: `def_local` パーサ＋エイリアス表の high-water-mark スコープ化（ブロック入口で位置記録→`END` で切り詰め）＋新別名種 `AL_VAR/AL_SVAR/AL_ARG/AL_SARG` を既存 slot ロード/ストアへ展開。`call_frame_t` に `save_var`/`save_svar` を追加し、`OP_CALL_SCRIPT` で退避＋0/空クリア・`OP_HALT` で復帰（＝`ARG`/`SARG`/`VAR`/`SVAR` が全て private ローカル・共有は `GVAR`/`SGVAR` のみ）。
12. **遅延post（v0.4.7）**: 文法 `send` に `[ "AFTER" expr ]`（ハンドラ源宛のみ・他は `ERR_BAD_POSITION`）、新opcode `POST_HANDLER_AFTER`〈portidx, argc〉（遅延はスタック top から pop・`<=0` は即post へ縮退）、vm に pending 表 `CFG_DELAY_SLOTS`(=4)（`event_t + due + init_armed` ≈180B/枠・payloadはpost時コピー）、`sched_tick` に満期スキャン→通常キューへ enqueue、INIT中は `init_armed` で t0 起点解決（`vm_arm_timer` と同手口）、pending 満杯は新STATUSビット `ERR_DELAY_FULL`(0x20)＋`def_const` 登録。`TIMER` は互換で据え置き。
13. **条件トリガ（v0.4.7）**: `ON <周期> ( 式 )` パーサ——条件式を**本体より前に独立チャンク**として吐き（`cond_start: <式> HALT`）、`block_t` に `cond_start`(2B)+`prev`(1B) を保持。`sched_tick` の周期満期で `cond_start` から `vm_exec` → スタック先頭の真偽を読み、`cond && !prev` で `run_handler`、最後に `prev = cond`。条件は int 必須（str は `ERR_TYPE_MISMATCH`）。**新opcode・新エラーコード・新STATUSビットすべて不要**（+64B のみ）。

各フェーズで上記サンプルが動くことを到達点にすると進めやすい。ホスト依存部（GPIO/UART/tick）はモック関数でユニットテスト可能。

## 16. 未決事項・将来のノブ

- **同tick混在イベントの順序**: 周期満期／`TIMER`満期／非同期post が同tickに重なったときの相互順序（v0未規定）。実機では「外部post優先」等を後日確定。なお**周期ハンドラ同士は定義順で確定済み**（§6）。
- **周期満期ポリシーのハンドラ個別修飾**: 現状はコンパイルオプションで全体一律（既定catch-up）。将来 `ON 1000 LATEST`（coalesce）/`ON 1000 EVERY`（catch-up）のようなハンドラ単位修飾を足す余地（§6）。
- **ハンドラのProtothreads化（v0.2+候補）**: 各 `ON` ハンドラをprotothread（Contiki etimer連携）として回し、ハンドラ内 `WAIT` を解禁する構想。待機フレーム管理をProtothreadsへ委譲できるため、§4の「全ハンドラ独立ローカル＝高コスト」が低コスト化する。解禁時は (a) `VAR`のWAITまたぎ非保証を全ハンドラに一般化（実装ゼロ）→ 不便なら (b) pt文脈に紐づく専用VAR面、の順。多重起動は「1ハンドラ1インスタンス・busy中の再postはオーバーフロー扱い」を既定候補とする。
- **大文字小文字**: 区別する/しない（サンプルは全大文字）。
- **文字列のエッジ検出**: `ON <周期> (条件)`（v0.4.7・§6）は int 純粋式のみ。文字列の変化検出は「更新箇所で `EQUALS` → メッセージ送信（post）」で代替する方針。専用構文は作らない。
- **分岐・同報・分流（生きてる木 / メッセージ分流）**: 将来。同報 `値 -> [A,B,C]` は一次元テキストに収まり軽い。合流ありDAGや常駐ノード網（生きてる木）は言語の芯が変わる大改造。今は見送り。`->` は合流しない「木」イメージ（始点から枝が生え、葉で終端、枝は交わらない）を基本線とする。
- **固定小数点**: 将来必要になったら追加（int32基準を維持）。
- **文字列の将来Utility**: `REPLACE` 等（同じ流儀＝1始まり・(開始,長さ)で追加）。`FINDER`/`STRTOL`/`FIELD`/`UPPER`/`LOWER`/`TRIMMER`/`CHR` は v0.4 系で採用済み（§3）。
- **マルチバイト文字列**: v0.3は1バイト1文字・ASCII前提。UTF-8等の文字単位処理は将来（`COUNTER`の文字数/バイト数の別など論点あり）。
- **`HANDLER` の複数化** `HANDLER[i]`（0..n・コンパイル時定数）: Cを書けるユーザーは `def_handler(NAME)` で任意名の self-post 源を**既に作れる**（`HANDLER` 一般化で実現済み・§10）。`HANDLER[i]` 連番は、**Cを書かないユーザーに既定の self-post レーンを複数与える**用途で将来候補として残す（既定インスタンスを `HANDLER` 1本から n本へ）。
- **VARのWAITまたぎ保持**: MAIN専用VAR面を持てば安価に実現可（必要を感じたら追加）／全ハンドラ独立ローカルは高コスト・非推奨（ただしProtothreads化で低コスト化、上項参照）。
- **各テーブル上限値**（GVAR/VAR/ARG数、ポート/ハンドラ数、スタック深さ、キュー長、タイマ本数=4、バイトコードバッファ、ネスト上限=4、**スクリプト内ポート呼び出し深さ `CFG_CALL_NEST`**=3〜4想定, v0.4.5）: ターゲットRAMに合わせ確定。コールフレームは `ret_pc`＋`ARG`/`SARG` 退避を含むので、`CFG_CALL_NEST × (ARG_COUNT×sizeof(value)+SARG_COUNT×SARG_LEN)` がRAM増分。ロード時の静的DAG判定で**実際の最大深度が `CFG_CALL_NEST` に収まることを検算**するため、これは「Cビルドで確保する上限」＝ロードが通れば実行時に溢れない保証値。
- **ロード起動の合図**: UART終端マーカー（例 `.run` 行）か長さ前置きか。
