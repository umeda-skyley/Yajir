# Yajir（ヤジール）

**超小型MCU向けの、小さな組み込みスクリプト言語**のリファレンス実装（純C）。名前の由来は構文の矢印（やじるし）`->`。

```
MAIN
    1 -> LED1        // 点ける
    500 -> WAIT      // 500ms 待つ
    0 -> LED1        // 消す
    500 -> WAIT
END

ON BTN               // ボタン押下イベント
    "pushed!" -> STDOUT
END
```

## Yajir の特徴

**FWを再ビルド・再フラッシュせずにアプリ層のロジックを流し込めるようにする**ための言語です。スクリプトはUARTからテキストで送り込み、その場（オンデバイス）でコンパイルして常駐実行します。主プログラムと同居させ、C ファームに1ソースとして統合して使う想定です。

こだわりの点：

* **省リソース** ── 「RAM 10Kでしっかり動く（”かろうじて”でなく）」
* **時間と非同期イベントの高い記述性** ── 組み込みの本質であるこの二要素を直観的に扱えるように
* **単一文法** ── 覚えるべき構文はなるべく少なく（できれば一つだけ）
* **暴走スクリプトが本体を壊さない** ── 配列超過でもゼロ除算でも、同居するFWは回り続けます
* **ミスを実行時に持ち越さない** ── スクリプトの記述ミスは実行時でなくロード時に検出して知らせます

## 設計思想 ── すべてはポート

**プログラムは `値 -> ポート` 構文で「的を矢で射る」。**

GPIOも、C関数も、`WAIT`も、`STDOUT`も、タイマも、メッセージの送出先も、条件分岐の制御フローまで、あらゆる対象を「**ポート**」（的、マト）という単一概念に畳みます。覚える文法カテゴリを極小にして、書き手が楽に・楽しく書けることを最優先します。省リソースを実現するためには、あきらめる所はスパッとあきらめ、複雑化へは持っていかないようにします。

技術的な骨格：

* **ヒープ不使用** ── 起動時に渡す固定RAMアリーナ1本だけで動く（`malloc` なし）。RAM使用量はコンパイル時に静的見積もり可能
* **スタック型バイトコードVM** ──スクリプト文字数に対して産出バイトコードが1/5-1/10ほどのコード体系
* **スーパーループ構造** ── ホストのメインループが `script_tick()` を駆動。スクリプト内は協調処理なので排他が不要
* **移植性** ── 移植はいくつかの必須関数を注入するだけでOK
* **意外と高い記述性** ── 一見、単純なことしかできそうにない言語ですが、実はかなり「書け」ます

## 3通りのLチカ ── 「時間の扱い方」が言語に見える

お馴染みの「LEDを100msで点滅」が3通り書けます。どれを選ぶかがそのまま設計判断になる、というのが Yajir らしさです。

**(1) `MAIN` にベタ書き** ── 一番素朴。ただし `MAIN` は1本しかないので、この時間軸を1つの処理が独占します。非推奨。

```
MAIN
    1 -> LED1
    100 -> WAIT          // WAIT はシステムを止めないが、MAIN のタイムラインは占有する
    0 -> LED1
    100 -> WAIT
END
```

**(2) 周期ハンドラ `ON <ms>`** ── 宣言的で、`MAIN` を空けたまま非同期に回る。`NOT LED1 -> LED1` は現在値を読んで反転（`LED1` は読み書き両用ポート）。

```
ON 100
    NOT LED1 -> LED1     // 100ms ごとにトグル
END
```

**(3) 遅延ポストで自走するハンドラ** ── ハンドラが「自分の続き」を N ms 後に予約して自分自身を再投入する。これが一番 Yajir らしい書き方 ── ハンドラが RTOS の協調型タスクのように振る舞い、独立した時間軸を好きなだけ並べられます。これで「LEDとブザーを別パターンで同時に」も難なくできます。

```
def_handler(BLINK)

INIT
    none -> BLINK AFTER 100      // 起動時に1発だけ蹴る（INITから予約できる）
END

ON BLINK
    NOT LED1 -> LED1
    none -> BLINK AFTER 100      // 自分をまた100ms後に呼ぶ＝自走
END
```

> `MAIN`+`WAIT` はタイムライン1本、遅延ポストはタイムラインN本。「時間軸を増やす／時間軸を生む」ための道具が言語に組み込まれている、というのが設計の中心にあります。

ほかにも ── ボタンのダブルタップ検出、しきい値をまたいだ瞬間だけ発火する条件トリガ（`ON 50 (ADC0 > 30)`）、サブルーチン、Yajirらしいエラーハンドラやステートマシンの実現方法 ── といったサンプルが [`scripts/`](scripts/) にあります。

## フットプリント（実測）

* **RAM** ： 標準構成で約 12 KB。キュー長・文字列スロット等の定数を調整すれば 5 KB 以下でもOK
* **Flash** ： 約 80 KB（Cortex-M4・デバッグビルド実測。最適化でさらに小さく）
* **動作実績** ： STM32 NUCLEO-L476RG（Cortex-M4）── Lチカ / ボタン / フィボナッチ ほか

バイトコード2 KB・文字列プール1 KB・スロット/ポート数などは [`src/core/script_config.h`](src/core/script_config.h) で調整できます。どの定数がどれだけ RAM に効くかは [`docs/resource_config.md`](docs/resource_config.md) にまとめてあります。ターゲットに合わせて削る／盛る際のガイドにしてください。

### 変更履歴（v0.4.8 → v0.4.9）

**現場要望まとめ**——実機で出た小粒な使い勝手要望を3点。(1)(2) は純コンパイル時糖衣（**新opcodeゼロ・バイトコード不変・実行時コストゼロ・追加RAMゼロ**）、(3) は文字列ユーティリティ1本。

**(1) 行継続 `\`（バックスラッシュ＋改行）** ── 長い文・長い構造化文字定数を物理行に折り返して書けるようにする。

* `\` の直後が改行なら **論理行を継続** する（バックスラッシュ・改行〈CRLF は1改行に畳む〉・**次行の行頭水平空白**をまとめて消す。行番号は進める）。効き方は文脈で変わる:
  * **文字列の外** ── `T_NEWLINE` を出さずに次行へつなぐ。文の途中どこでも折り返せる（`def_alias(NAME, \`〈改行〉、引数リストの途中 `A, B, \`〈改行〉`C -> MAP`、チェインの `->` 直前で切る等）。
  * **文字列の中** ── 文字列を継続し、**行頭のインデントを値に含めない**（整形の字下げが値を汚さない）。次は `"xxxx|yyyy|zzzzzzz"` と厳密に同値:

```
def_alias(CONV_TABLE, "xxxx|\
                       yyyy|\
                       zzzzzzz")
```

* 意味論: 行頭空白は**捨てる**（単一行版と厳密に同値）。意図的な空白は `\` の“前”に置けば残る。折り返す各物理行の末尾に `\` が要る。**裸の改行（`\` なし）は従来どおりエラー**（文字列は明示継続しない限り1行）。意味を与える対象（文字列内 `\`+改行／文字列外の裸 `\`）はどちらも現状エラーになる並びゆえ**後方互換**（有効な既存スクリプトは1つも挙動が変わらない）。

**(2) ビルド設定定数 `CFG_*` をスクリプトから参照可能に** ── スロット数・文字列長をプラットフォーム非依存で書ける。

* `CFG_*` を式の値位置で **int リテラルへ展開** するコンパイル時定数。値は「そのビルドの `script_config.h` の実値」。だから移植先の設定に自動追従する:

```
CFG_VAR_COUNT -> REPEAT
    ITR -> VAR              // VAR[0..CFG_VAR_COUNT-1] を過不足なくなめる
END
```

* **ポートも alias スロットも消費しない**（`def_const`／`def_alias` とは別枠。使わない人のコストゼロ）。**読み取り専用**・**予約名**（`def_alias` で上書き不可）。公開は移植に要る**「寸法」定数14個に限定**（スロット数・文字列長・資源スロット数。内部限界 `CFG_CODE_SIZE`/`CFG_INSTR_BUDGET` 等は非公開）。

**(3) 文字列ユーティリティ `ASC`（文字→数値）を追加** ── `CHR`（int→1文字str）の対。

* `"A" -> ASC` → `65`。**文字列の先頭1バイトを 0..255 で返す。空文字列は 0**（`RESULT` 産出）。これまで欠けていた「文字→数値」の一発変換。`'A'` は Yajir では既に int なので `ASC` の入力は文字列が自然（`90 -> CHR -> ASC` == 90 で往復）。
