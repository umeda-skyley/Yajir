# Yajir（ヤジール）

超小型MCU向けの、小さな組み込みスクリプト言語のリファレンス実装（純C）。

**「すべてはポート。`値 -> ポート` で値を流す」** ── この一つの発想だけで、
GPIO・UART・タイマ・文字列処理・イベントを、同じ記法で扱います。

```
MAIN
    1 -> LED1        // 点ける
    500 -> WAIT      // 500ms 待つ
    0 -> LED1        // 消す
    500 -> WAIT
END

ON BTN               // ボタン押下イベント
    "pushed!" -> STDOUT
END
```

- **ヒープ不使用** ── 固定RAMアリーナ1本だけで動く（`malloc` なし）
- **スタック型バイトコードVM** ＋ ワンパスコンパイラ ＋ 協調tick
- **ホスト非依存のコア** ── ボード側は「ポートを register するグルー」を差し替えるだけ
- 端末からスクリプトを貼り付け → その場でコンパイル＆常駐実行

## フットプリント（実測）

| | |
|---|---|
| **RAM** | 約 **10 KB**（VMアリーナ1本・ヒープ不使用。実機ローダは受信バッファ込みで約14 KB） |
| **Flash** | 約 **24 KB**（Cortex-M4 コア一式。デバッグビルド実測、最適化でさらに小さく） |
| **動作実績** | STM32 NUCLEO-L476RG（Cortex-M4）── Lチカ / ボタン / フィボナッチ ほか |

バイトコード2 KB・文字列プール1 KB・スロット/ポート数などは `src/core/script_config.h` で調整できます。

## 収録物

- `src/core/` ── 言語コア（VM・コンパイラ・スケジューラ・文字列ユーティリティ）
- `src/host/` ── PC（Windows）ホストと STM32 実機ホスト
- `tests/`    ── フェーズ別ユニットテスト
- `docs/` / `scripts/` ── 組み込みポート早見表とサンプルスクリプト（`.yaj`）

## 変更履歴

### 変更履歴（v0.4.4 → v0.4.5）

**スクリプト内ポート定義 `PORT … END`（＝戻り値を返すサブルーチン）＋ `EXIT` を `値 -> EXIT` に拡張**（§3, §4, §7）。従来スクリプト内で書けるユーザー定義ブロックは `ON … END`（ハンドラ＝遅延・戻り値なし・右辺専用）だけだったが、ここに**同期・値を返す**もう一系統＝**スクリプト内ポート**を足す。ユーザーから見れば要するに**サブルーチン**。

- **`def_port(NAME, T_INT|T_STR)` ＋ `PORT NAME … END`**: C を1行も書かず、組み込みの関数ポート（`FORMATTER` 等）と**同格の `inout` ポート**を定義できる。`->` の両辺に置け・チェインできる（`1,3 -> SUM -> STDOUT`）。産出は `RESULT`/`SRESULT` に乗るのでチェインも型チェックも既存機構がそのまま効く。
- **引数と共有**: 引数は `ARG`/`SARG` で受ける（**VMが自動退避/復帰する真の仮引数**＝呼び出し元の受信引数は壊れない）。`VAR`/`SVAR` は**呼び出し元と共有**（サブルーチンの作業場・私的ローカルは持たない）。
- **`値 -> EXIT`**: スクリプト内ポートは戻り値を返す。ハンドラ内は値を捨てて早期リターン。**単独 `EXIT` は「戻り型のデフォルト値（`0`/空文字）を返す略記」として存続＝後方互換**（既存スクリプトはそのまま通る）。`EXIT` されず `END` 到達は `0`/空文字を産出。
- **制約（実装を軽く保つ要）**: 本体内 `WAIT` は不可（`REPEAT` と同じ **within-tick**）。**再帰は自己・相互とも禁止**——スクリプト内ポート呼びは全てリテラル名（動的ディスパッチ無し）ゆえ、**ロード末尾に呼び出しグラフの DFS を1回**回してサイクルを検出（専用 `ERR_RECURSION`＋ポート名）、同じDFSで最大コールスタック段数も静的に検算（`CFG_CALL_NEST` 超過は `ERR_NEST_TOO_DEEP`）。実行時に溢れることは到達不能。
- 実装: VM初導入の同期呼び出し（戻り番地スタック）。新opcode `CALL_SCRIPT`/`STORE_RESULT`＋`HALT` の文脈依存化、`CFG_CALL_NEST=4`。ユニットテスト `tests/test_phase12_ports.c`（37チェック）、サンプル `scripts/subroutines.yaj`（点数レポート＝int/str サブルーチン・早期EXIT・`REPEAT` で棒グラフ組み立て・チェイン）を追加。

### 変更履歴（v0.4.3 → v0.4.4）

**有界ループ `REPEAT` ／ 反復カウンタ `ITR` ／ スロットの動的添字アクセス `N -> SLOT` の3点セット**（§3, §4, §7）。初期の割り切り「ループ無し・添字は定数のみ」を、実用スクリプトの配列反復のために2つとも解く。安全性は既存の命令数バジェットと benign-0 縮退でほぼ据え置き（後方互換）。

- **`N -> REPEAT … END`（有界ループ）＋ `ITR`（1..N）**: 本体を N 回実行、`ITR` は本体内だけの反復カウンタ（1始まり・最内ループを指す）。ネストは `CFG_LOOP_NEST=4` 段。**`REPEAT` 内で `WAIT` はコンパイルエラー（`ERR_WAIT_IN_LOOP`）**——これにより `REPEAT` は「1 tick 内で完結し決してティックをまたがない within-tick 構造」になり、ループ状態を yield またぎで永続化する必要が無い。深い N は命令数バジェット超過で **`END` の直後へ打ち切り＋`ERR_BUDGET`**（クラッシュせず観測可能）。役割の線引き＝`REPEAT` は同期・within-tick の計算用、時間を進める反復は従来どおり `ON <周期>`／self-post。
- **動的添字 `N -> SLOT`（read）／`idx, val -> SLOT`（write）**: スロット名を裸のポートとして使うと実行時に決まる添字でアクセスできる。**第1引数が添字（1始まり）**——`N -> VAR` は `VAR[N-1]` を産出、`idx, val -> VAR` は `VAR[idx-1] = val` して書いた値を産出。産出型はスロットの要素型なので**そのままチェインに乗る**（`ITR -> VAR -> STDOUT` 走査・`ITR, 式 -> VAR` 充填）。範囲外は benign（read=0/空文字、write=no-op）でメモリ安全は実行時境界チェックが担保。書く値の型は静的 `ERR_TYPE_MISMATCH`、`ARG`/`SARG` は read のみ（write は `ERR_BAD_POSITION`）。
- 実装: 新opcode `REPEAT_INIT`/`REPEAT_NEXT`/`LOAD_ITR`/`INDEX`、vm 構造体にループフレーム、`CFG_LOOP_NEST=4`。ユニットテスト `tests/test_phase11_loops.c`（30チェック）、サンプル `scripts/loopdemo.yaj`（配列を乱数充填→走査で合計/最大）・`scripts/wolfram_ca.yaj`（Rule 30 一次元セルオートマトン）を追加。

### 変更履歴（v0.4.2 → v0.4.3）

**数値ユーティリティ・ポート群を標準装備に追加（`RAND`/`SEED`・`CLAMP`・`MAP`・`MIN`/`MAX`・`ABS`）＝ 文字列ユーティリティ（`SLICER` 等）の数値版**（§3, §9）。「変換はポート」に則り、乱数・飽和・線形写像・最小/最大/絶対値を int産出のポートとして提供する。`register_mathutils()` を `register_builtins()` から呼ぶ形で、文字列版（`register_strutils`）と同じ骨格・同じ登録経路に乗せた。

- **`RAND`（in・非負乱数源）＋ `SEED`（out・再シード）**: `RAND` は 0..2³¹-1 の非負整数を1つ産む値源（範囲は既存の `%` で作る＝`RAND % 6 + 1` でサイコロ）。実体は **libc `rand()` に移譲せず自前の xorshift32**（状態1ワードをアリーナ内 `rng_state` に置く・再現的・full 32bit・状態0は既定種へ自動退避）。符号ビットを落として非負域に固定し、`RAND % N` が負にならないことを保証。`値 -> SEED` でスクリプトから再シード（`NOW -> SEED` で実行ごとに列を変える）、ホストは起動時に `script_srand(entropy)` でADC雑音/UID等の種を注入できる。※暗号用途ではない（ジッタ/バックオフ/ディザ/ゲーム向けの実用乱数）。
- **`CLAMP`（x,lo,hi）/ `MAP`（x,inLo,inHi,outLo,outHi）**: 組み込みの定番。`CLAMP` は値を範囲に飽和、`MAP` は Arduino `map()` 相当の線形リスケール（ADC→実単位）。`MAP` は中間積を int64 で計算してオーバーフローを回避し、`inHi==inLo`（レンジ幅0）は既存の 0除算方針どおり `RESULT=0`＋`ERR_DIVZERO`（止めずにフラグで気づく）。`MAP` はレンジ外を外挿するので、端で止めたいときは `CLAMP` と併用する。
- **`MIN`/`MAX`（可変長）・`ABS`**: 縮約と絶対値。`ABS(INT32_MIN)` は反転不能（UB）ゆえ `INT32_MAX` に飽和させる。
- 付随: `CFG_MAX_PORTS 48→56`（組込みポートが29本になったため余裕を確保）。ショーケース `scripts/mathdemo.yaj`（模擬ADC→`MAP`→`CLAMP`→`MIN`/`MAX`/`ABS` の一連）と、ユニットテスト `tests/test_phase10_math.c`（26チェック）を追加。

### 変更履歴（v0.4.1 → v0.4.2）

**値の型を int / str の2択に純化する（内部 CHAR タグを撤去）＋ 文字リテラル `'A'` ＋ 変換Utility `CHR` の3点セット**（§2, §3, §5, §9, §10, §11）。

- **内部 `CHAR` 型を撤去し、値は int か str の2択に純化**（§9）。従来 VM 値は `int / char / str` の3タグ（`char`＝「.i に文字コードを持つ整数で、STDOUT はグリフ表示する」）だったが、`char` は**型というより「出力時のレンダリング指示が値に相乗りしているだけ」**で、実効は STDOUT の1分岐のみ。しかも `GVAR`（int スロット）を1回通るとタグは落ちる＝**直の `ARG[0] -> STDOUT` 一発しか生きない脆いタグ**で、実質「型」ではなかった。これを撤去し「**値は数か文字列。数を文字グリフとして描くかは出力側の仕事**」に整理する。撤去対象: 値タグ `SV_CHAR`／`val_char`／host STDOUT の char 分岐／`script_post_msg_char`・`SCRIPT_ARG_CHAR`（int 版と同義なので薄い互換別名として温存）。UART RX 1バイトは**ただの int** として `ARG[0]` に入る。
- **文字リテラル `'A'` を字句として追加（＝整数リテラルの別表記）**（§2）。`0x41` や `65` と完全に同格の「整数の綴り違い」。`'A'` は int 値 65 を積むだけで、専用タグは持たない。ゆえに `'A' -> GVAR[0]`（int スロット）はOK、`(ARG[0] == 'A')` は素直な int 比較（`== 65` より可読）、`'A' + 1` は int 算術。`'A' -> SVAR[0]`（str スロット）は型違いで `ERR_TYPE_MISMATCH`。エスケープは文字列と同じ `'\r' '\n' '\t' '\\' '\''`。空 `''`・複数文字 `'AB'` は字句エラー。実装は**トークナイザが int リテラル（int値）として吐くだけ**で parse は無改修・新しい値タグや型は増えない。
- **変換Utility `CHR`（int→1文字str）を標準装備に追加**（§3）。CHAR タグ撤去で「数を文字グリフで出す」置き場が要るが、これは**出力側のポート**に持たせる＝ Yajir の「変換はポート」（`STRTOL`＝str→int の対）に一致。`65 -> CHR` → `SRESULT`=`"A"`。UART エコーは `ARG[0] -> CHR -> STDOUT` と書く（`FORMATTER "%c"` の一引数糖衣に相当。`FORMATTER` の `%c` は従来どおり int を受けてグリフ化するので温存）。
- **帰結（後方互換の注意）**: 旧イディオム `ARG[0] -> STDOUT`（受信文字のエコー）は、グリフではなく**10進数**を出すようになる。エコーは `ARG[0] -> CHR -> STDOUT`（または `"%c", ARG[0] -> FORMATTER -> STDOUT`）へ書き換える。1.0前ゆえ許容とするが破壊的変更として明記。得るもの＝型モデルが int/str の2択に純化・`'A'` が「整数の別表記」として一貫・変換が全部ポートに乗る世界観の統一。

**制御語 `EXIT` を追加（ON ハンドラの早期リターン）**（§3, §7, §13。コードは v0.4.1 で先行導入・ここで正式記載）。`ON … END` 内で、エラー条件等により**そのハンドラを途中で即終了**したいときに書く裸の制御語（`END`/`ELSE` と同じ制御語カテゴリ・`-> 送り先` を伴わない）。ネストした `IFYES` の内側からでもハンドラ**全体**を抜ける（C の `return` 相当・`break` のような一段だけの脱出ではない）。**`INIT`/`MAIN` 内では構文エラー**（`ERR_SYNTAX`）＝ON専用（`WAIT` の「ON不可」判定のちょうど逆で、`yield_ok` フラグで静的判別）。実装は**新opcode不要**——その場で既存の `OP_HALT`（ブロック終端＝`EXEC_DONE`）を吐くだけで、ON ハンドラは yield せず走り切る（resume状態を持たない）ので早期HALTが安全に効く。

### 変更履歴（v0.4 → v0.4.1）

- **ISR から `script_post_msg*` を直接呼べるよう正式化＝イベントキューを MPSC 安全化**（§10, §11, §12）。従来「post は ISR安全（積んで即return）」と述べつつ、実体のSPSCリングは**単一生産者前提**だった。Yajir はスクリプト自身が self-post でき（`値 -> ハンドラ源`・`INVOKER`＝メイン文脈の生産者）、加えて生ISRからも post したい（ボタンEXTI／UART RX 等）ため、生産者が複数になり `evq_tail` 更新が競合しうる（低頻度ゆえ実害は出にくいが潜在レース）。**enqueue（`evq_push` のtail公開）を短いクリティカルセクションで囲い MPSC 安全にする**ことで、「任意のISRから直接 post してよい」を保証へ格上げ。**disable_irq 相当はプラットフォーム依存**なので、コアは `YJ_ENTER_CRITICAL()` / `YJ_EXIT_CRITICAL()` の2マクロ越しに囲み、**コアは既定で空定義（純C・ホスト非依存を維持）**・各ホストが自ターゲットの割り込み禁止/復帰へ割り当てる（STM32=CMSIS の `PRIMASK` 退避 `__get_PRIMASK()`/`__disable_irq()`/`__set_PRIMASK()`）。単一生産者しか無いホストは空マクロのままでよい（コスト厳密ゼロ）。dequeue（消費）はメインループ1本のままで不変。新opcode無し・言語文法変更無し。ホストサンプルの「ISRではフラグだけ立て、実postはメインループ」という回避策は本対応で不要になる。
- **`def_handler(NAME)` をスクリプト側宣言として正式採用**（§3, §10, §13）。従来ハンドラ源は C側 `script_register_handler` が唯一の登録経路で、スクリプトの `def_handler` 行は非解釈のドキュメントだった。**handler はポート種別で唯一「束縛すべきCの実体（関数/値）を持たない＝名前だけのイベントチャネル」**なので、`def_alias`（v0.3.8）に続き**コンパイラが実際に解釈する2つ目の `def_`** に格上げする：`def_handler(NAME)` はコンパイル時にハンドラ源ポートを1本 `add_port` し、以後 `ON NAME` と `値 -> NAME`（self-post）が普通に解決される。これで **Cを1行も書かず、スクリプト内だけで完結する名前付きハンドラ／状態機械**（`INVOKER` 動的発火・self-post 反復と併用）が書ける。意味は**「このハンドラ源の存在を保証する（冪等）」**——C側が既に同名を register 済みなら no-op（同種再束縛）、無ければ新規に生やす。ゆえに既存スクリプトの `def_handler(UART1)`（Cが登録済み）等は**挙動不変で後方互換**。`def_in`/`def_out`/`def_inout` は**C関数ポインタが必須**ゆえスクリプト側では作れない（引き続き非解釈ドキュメント）＝「Cが要るものはC側、名前だけで済む handler はスクリプト側」の線引き。構文は既存 `def_*`／`def_alias` に合わせ **bare identifier**（`def_handler(RETRY)`・クォート無し）、宣言は使用より前（`def_alias` と同様に冒頭一括）。**衝突**（予約語/スロット名/既登録の非handlerポートと同名）は `ERR_SYNTAX`、**ポート表満杯**は新設 `ERR_TOO_MANY_PORTS`（従来の add_port 満杯時「黙ってNULL＝無言で登録失敗」を、スクリプト経路では load エラーへ格上げ＝実装で踏んだ無言オーバーフローの再発防止）。
