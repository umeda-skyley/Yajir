# Yajir（ヤジール）

超小型MCU向けの、小さな組み込みスクリプト言語のリファレンス実装（純C）。

**「すべてはポート。`値 -> ポート` で値を流す」** ── この一つの発想だけで、
GPIO・UART・タイマ・文字列処理・イベントを、同じ記法で扱います。

```
MAIN
    1 -> LED1        // 点ける
    500 -> WAIT      // 500ms 待つ
    0 -> LED1        // 消す
    500 -> WAIT
END

ON BTN               // ボタン押下イベント
    "pushed!" -> STDOUT
END
```

- **ヒープ不使用** ── 固定RAMアリーナ1本だけで動く（`malloc` なし）
- **スタック型バイトコードVM** ＋ ワンパスコンパイラ ＋ 協調tick
- **ホスト非依存のコア** ── ボード側は「ポートを register するグルー」を差し替えるだけ
- 端末からスクリプトを貼り付け → その場でコンパイル＆常駐実行

## フットプリント（実測）

| | |
|---|---|
| **RAM** | 約 **10 KB**（VMアリーナ1本・ヒープ不使用。実機ローダは受信バッファ込みで約14 KB） |
| **Flash** | 約 **24 KB**（Cortex-M4 コア一式。デバッグビルド実測、最適化でさらに小さく） |
| **動作実績** | STM32 NUCLEO-L476RG（Cortex-M4）── Lチカ / ボタン / フィボナッチ ほか |

バイトコード2 KB・文字列プール1 KB・スロット/ポート数などは `src/core/script_config.h` で調整できます。

## 収録物

- `src/core/` ── 言語コア（VM・コンパイラ・スケジューラ・文字列ユーティリティ）
- `src/host/` ── PC（Windows）ホストと STM32 実機ホスト
- `tests/`    ── フェーズ別ユニットテスト
- `docs/` / `scripts/` ── 組み込みポート早見表とサンプルスクリプト（`.yaj`）

## 変更履歴

### 変更履歴（v0.4 → v0.4.1）

- **ISR から `script_post_msg*` を直接呼べるよう正式化＝イベントキューを MPSC 安全化**（§10, §11, §12）。従来「post は ISR安全（積んで即return）」と述べつつ、実体のSPSCリングは**単一生産者前提**だった。Yajir はスクリプト自身が self-post でき（`値 -> ハンドラ源`・`INVOKER`＝メイン文脈の生産者）、加えて生ISRからも post したい（ボタンEXTI／UART RX 等）ため、生産者が複数になり `evq_tail` 更新が競合しうる（低頻度ゆえ実害は出にくいが潜在レース）。**enqueue（`evq_push` のtail公開）を短いクリティカルセクションで囲い MPSC 安全にする**ことで、「任意のISRから直接 post してよい」を保証へ格上げ。**disable_irq 相当はプラットフォーム依存**なので、コアは `YJ_ENTER_CRITICAL()` / `YJ_EXIT_CRITICAL()` の2マクロ越しに囲み、**コアは既定で空定義（純C・ホスト非依存を維持）**・各ホストが自ターゲットの割り込み禁止/復帰へ割り当てる（STM32=CMSIS の `PRIMASK` 退避 `__get_PRIMASK()`/`__disable_irq()`/`__set_PRIMASK()`）。単一生産者しか無いホストは空マクロのままでよい（コスト厳密ゼロ）。dequeue（消費）はメインループ1本のままで不変。新opcode無し・言語文法変更無し。ホストサンプルの「ISRではフラグだけ立て、実postはメインループ」という回避策は本対応で不要になる。
- **`def_handler(NAME)` をスクリプト側宣言として正式採用**（§3, §10, §13）。従来ハンドラ源は C側 `script_register_handler` が唯一の登録経路で、スクリプトの `def_handler` 行は非解釈のドキュメントだった。**handler はポート種別で唯一「束縛すべきCの実体（関数/値）を持たない＝名前だけのイベントチャネル」**なので、`def_alias`（v0.3.8）に続き**コンパイラが実際に解釈する2つ目の `def_`** に格上げする：`def_handler(NAME)` はコンパイル時にハンドラ源ポートを1本 `add_port` し、以後 `ON NAME` と `値 -> NAME`（self-post）が普通に解決される。これで **Cを1行も書かず、スクリプト内だけで完結する名前付きハンドラ／状態機械**（`INVOKER` 動的発火・self-post 反復と併用）が書ける。意味は**「このハンドラ源の存在を保証する（冪等）」**——C側が既に同名を register 済みなら no-op（同種再束縛）、無ければ新規に生やす。ゆえに既存スクリプトの `def_handler(UART1)`（Cが登録済み）等は**挙動不変で後方互換**。`def_in`/`def_out`/`def_inout` は**C関数ポインタが必須**ゆえスクリプト側では作れない（引き続き非解釈ドキュメント）＝「Cが要るものはC側、名前だけで済む handler はスクリプト側」の線引き。構文は既存 `def_*`／`def_alias` に合わせ **bare identifier**（`def_handler(RETRY)`・クォート無し）、宣言は使用より前（`def_alias` と同様に冒頭一括）。**衝突**（予約語/スロット名/既登録の非handlerポートと同名）は `ERR_SYNTAX`、**ポート表満杯**は新設 `ERR_TOO_MANY_PORTS`（従来の add_port 満杯時「黙ってNULL＝無言で登録失敗」を、スクリプト経路では load エラーへ格上げ＝実装で踏んだ無言オーバーフローの再発防止）。
